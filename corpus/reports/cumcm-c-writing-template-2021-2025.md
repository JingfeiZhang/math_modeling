# 国赛 C 题论文写作模板

## 1. 证据范围与使用边界

本模板基于 2021-2025 年全国大学生数学建模竞赛 C 题展示论文的页面级精读，不以文件名、社区评价或算法复杂度代替论文质量判断。

## 2. 从优秀论文中确认的稳定规律

### 2.1 摘要承担第一轮完整答题

14 篇样本均在第一页完成摘要，没有先放目录。较好的摘要不是算法清单，而是按照子问题依次回答：

1. 本问解决什么；
2. 使用什么数据和模型；
3. 得到什么量化结果；
4. 如何验证；
5. 结论在什么条件下成立。

直接证据包括：C066、C155、C050、C228、C038、C023、C132 的 PDF 第 1 页。C228 和 C132 的摘要尤其完整，既写数据处理与模型链，也给关键数值和验证结果。

### 2.2 前置章节先完成导航和口径统一

多数样本在进入问题一之前已经处理问题重述、问题分析、模型假设、符号和共同数据口径。例如：

- C066：问题重述与分析 p.2，假设与符号 p.3，数据处理 p.4；
- C155：重述与假设 p.2，符号与分析 p.3-4；
- C228：重述 p.2，假设 p.2，分析 p.3，符号 p.4，数据预处理 p.4-6；
- C132：重述 p.2，分析 p.3-4，假设 p.4，符号 p.5，数据预处理 p.6-7。

因此，问题重述、问题分析、假设、符号和共享数据处理应放在正文前部，不应把符号表移到附录。

### 2.3 各问内部形成独立闭环

高质量问题章节普遍遵循：

```text
问题目标与接口
→ 数据特征或机理依据
→ 模型选择
→ 变量、目标和约束
→ 求解算法与参数
→ 结果图表
→ 误差、敏感性、稳健性或可行性检查
→ 本问结论与下一问接口
```

C228 的问题二 p.16-22、C038 的问题一 p.5-24、C132 的问题二 p.11-20 都具有完整链条。相反，只写算法定义和输出表、没有基线或检验的章节，阅读上明显不完整。

### 2.4 图表用于证据，不用于装饰

优秀样本中的图表主要承担四种职责：

- 数据结构：分布、相关、时序和异常诊断；
- 模型机制：变量关系、算法流程、状态转移；
- 主结果：预测、排序、决策方案、收益或风险；
- 模型检验：残差、扰动、情景、阈值和稳定性。

典型页面包括 C155 p.6-24、C228 p.15、p.18-22、p.29，C038 p.21-23、p.30-32、p.40-42，C023 p.19-21，C132 p.8-10、p.19-20、p.27-30。

### 2.5 模型评价写本文边界，不写教材优缺点

C283 p.26-28、C094 p.22、C234 p.24、C023 p.22、C132 p.34-35 都将评价落到具体变量、假设、随机性、数据范围和算法边界。模板应避免“算法先进、精度较高、模型科学”这类无证据结论。

### 2.6 长代码附录是历史样本的共同缺陷

多篇论文的附件远长于正文，例如 C126 p.20-74、C228 p.31-70、C094 p.23-58、C132 p.36-65。C023 前 28 页采用“文件索引 + 关键说明”的方式更利于阅读。未来提交应采用“论文附录展示关键代码，支撑包保存完整源码和运行入口”，不要把全部工程代码逐页粘贴进论文。

### 2.7 官方展示页可继续扩展，但只迁移结构

教育部中国大学生在线的官方栏目提供统一的历年入口：

- 总入口：<https://dxs.moe.gov.cn/zx/hd/sxjm/sxjmlw/qkt_sxjm_lw_lwzs.shtml>
- 2025：<https://dxs.moe.gov.cn/zx/hd/sxjm/sxjmlw/2025qgdxssxjmjslwzs/>
- 2024：<https://dxs.moe.gov.cn/zx/hd/sxjm/sxjmlw/2024qgdxssxjmjslwzs/>
- 2023：<https://dxs.moe.gov.cn/zx/hd/sxjm/sxjmlw/2023qgdxssxjmjslwzs/2023gjsbqgdxssxjmjslwzs.shtml>
- 2022--2021：从总入口进入对应年度栏目，先核对封面、题号和展示身份再纳入样本。

当前工作区已登记并完成页面级复核的近年样本包括 2024 C038、C063、C094、C234 和 2025 C023、C132；同年度 A/B/D/E 论文用于比较不同题型的摘要、流程图、约束和验证表达。新增论文必须先记录官方 URL、页面哈希、题号和复核页码，不能以社区文件名或“优秀论文”标签直接认定奖级。官方论文仅用于观察：

1. 摘要如何在一页内完成逐问交付；
2. 前置章节如何统一数据、符号和问题接口；
3. 结果图表如何与模型检验和决策建议衔接；
4. 局部结果、近似解和模型边界如何诚实表述。

不得复制论文文字、数据、图件、代码或结论，也不得把展示论文转入 Academic Reference Card、Formal evidence、claims、正文引用或附件。

## 3. 推荐的固定总结构

```text
首页
摘要
关键词

1  问题重述
2  问题分析
3  模型假设与符号约定
4  数据处理与评价指标
5  问题一：模型建立与求解
6  问题二：模型建立与求解
7  问题三：模型建立与求解
8  问题四：模型建立与求解（仅实际存在时）
9  模型评价与推广

参考文献
附录
```

若当届规则要求 AI 工具使用声明，将声明放在正文结束、参考文献之前。正文技术论述和图注不重复工具说明。

正文不设置目录，不为不存在的子问题保留空章，不为每个问题强制另起一页。

## 4. 各模块的写作规范

### 4.1 论文标题

**表达目标**：用一句话标明研究对象、核心任务和主要模型性质，让评委在摘要前知道论文解决了什么。

**必须写**：

- 研究对象；
- 主要决策或分析目标；
- 只有真正构成主线的方法才进入标题。

**推荐形式**：

```text
基于[核心机制/模型]的[研究对象][分析/预测/评价/优化]
面向[应用目标]的[研究对象]多阶段决策模型
```

**禁止**：堆叠三个以上算法名；使用“研究与分析”“模型研究”等无法区分任务的宽泛标题。

### 4.2 摘要

**表达目标**：在一页内独立回答所有子问题，使评委不翻正文也能知道方法、结果、验证和边界。

**固定结构**：

1. 总述段：研究对象、核心矛盾、统一数据口径和总体模型链；
2. 问题一段：方法、关键结果、验证；
3. 问题二段：与问题一的接口、模型、关键结果、对比；
4. 问题三段：新增状态或约束、方法、关键结果；
5. 问题四段：扩展、综合或最终决策及其结果；
6. 收束句：总体检验、适用范围或最重要边界；
7. 关键词：3-5 个领域词和方法词。

**每问句式骨架**：

```text
针对问题 x，基于[数据/前问结果]，构建[模型]，并采用[求解方法]得到[带单位的关键结果]；
[基线/误差/覆盖率/约束审计/敏感性]表明[验证结论]。
```

**质量门槛**：

- 每问至少一个量化结果或明确交付物；
- 优先写模型针对题目做了什么，不介绍教科书原理；
- 摘要中的数字必须能在正文表格或图件中定位；
- 不使用“效果很好”“具有实际意义”替代数值。

### 4.3 问题重述

**表达目标**：把题面转换成清晰的输入、输出和子问题依赖，不讨论算法。

**建议结构**：

```text
1.1 研究背景与对象
1.2 问题一的输入和要求输出
1.3 问题二的输入和要求输出
1.4 问题三的输入和要求输出
1.5 问题四的输入和要求输出
1.6 子问题之间的依赖关系（仅关系复杂时）
```

**必须回答**：

- 给了哪些数据、规则和约束；
- 每问要求计算、预测、评价或优化什么；
- 前一问的输出是否进入后一问；
- 最终结果以何种形式提交。

**禁止**：复制题面大段文字；提前写算法；提前报告最终结论；增加与赛题无关的行业背景。

### 4.4 问题分析

**表达目标**：说明每问的数学本质、难点、变量关系和模型选择逻辑。

**每问固定回答六项**：

1. 数学类型：统计推断、预测、分类、评价、规划、调度或机理分析；
2. 输入、状态、决策变量和输出；
3. 主要冲突：精度与解释性、收益与风险、成本与服务、短期与长期等；
4. 数据或题面难点：缺失、零膨胀、非平稳、整数约束、不确定性等；
5. 候选方法及放弃理由；
6. 与前后问题的数据接口。

**推荐论证句式**：

```text
该问本质上是[数学类型]。数据具有[可核验特征]，同时受到[关键约束]限制。
相较于[候选方法]，[采用方法]能够处理[本题特征]；其代价是[具体边界]，后文通过[检验]评估该影响。
```

**流程图使用条件**：只有当三个以上子问题存在明确数据流、状态传递或模型复用时使用。图中只保留输入、核心处理、模型、输出和验证，不把全部算法步骤堆入总流程图。

### 4.5 模型假设

**表达目标**：公开说明为了可求解而简化了什么，并给出结论的适用边界。

**每条假设必须包含**：

- 假设对象；
- 简化内容；
- 采用理由；
- 可能影响的结果或边界。

**可接受例子**：在预测窗口内设备容量不变；同一时间粒度内价格按已知值处理；未观测扰动并入随机误差项。

**禁止**：假设数据真实可靠；忽略一切偶然因素；假设模型正确；假设所有条件不变。

### 4.6 符号约定

**表达目标**：保证公式、表格和代码使用同一语言。

全局符号表只保留跨章节反复使用的变量，列为：

```text
符号 | 含义 | 单位/取值域 | 首次使用位置
```

局部变量在公式后解释，不把数十个只出现一次的下标塞入全局表。符号表不在附录重复。

### 4.7 数据处理与评价指标

**表达目标**：解释哪些处理改变了模型输入和结论口径，并建立各问共享的数据接口。

**推荐结构**：

```text
4.1 数据字段、时间粒度和空间粒度
4.2 缺失、重复和异常处理
4.3 变换、标准化和特征构造
4.4 训练、验证、测试或情景划分
4.5 评价指标、单位和共同约束
```

**每项处理都要写四件事**：

1. 发现了什么问题；
2. 使用什么规则处理；
3. 为什么采用该规则；
4. 处理会怎样影响后续模型。

优秀样本中可借鉴的表达包括 C126 对零膨胀与 MCMC 计算压力的说明、C228 对自然连接和多时间粒度聚合的说明、C235 对候选方法不适用性的说明、C132 对重复测量和个体差异的处理。

**指标要求**：给出公式、单位、方向和使用场景。预测指标不能混用训练集与测试集；优化指标必须说明基线；分类指标需说明阈值和类别不平衡；统计检验需写原假设、显著性水平和结论方向。

## 5. 每个子问题的固定内部模板

每个问题章节采用七段结构。标题可因题型略作调整，但论证内容不能缺失。

### x.1 问题目标与前后接口

**目标**：限定本问要解决的唯一核心任务。

**写什么**：输入、输出、决策或状态变量；使用前一问的哪些结果；输出给下一问什么。

**结束句**：明确本问将以哪个指标判断完成。

### x.2 数据特征、机理与模型选择

**目标**：让模型选择由题目证据驱动。

**写什么**：与本问直接相关的数据诊断或机理；2-3 个候选方法的适用性；最终方法的选择理由和代价。

**证据**：一张必要的数据图或一个简短统计表即可。若前置数据章已经证明，不重复作图，只引用。

### x.3 模型建立

**目标**：把题目语言变成可计算的数学对象。

**固定顺序**：

1. 决策变量和状态变量；
2. 参数及来源；
3. 目标函数或统计模型；
4. 关键约束；
5. 边界和初始条件；
6. 变量之间的逻辑关系；
7. 必要的线性化、变换、正则化或松弛。

每个公式后必须解释实际含义。正文只写支撑结论的核心公式，不抄教材完整推导。

### x.4 模型求解与算法

**目标**：说明结果如何从模型得到，并使求解过程可以复现。

**必须写**：

- 软件、求解器或算法；
- 初始化或训练方式；
- 关键参数及取值依据；
- 迭代、搜索或滚动过程；
- 停止条件；
- 数据规模和运行规模；
- 硬约束如何保证；
- 随机种子或重复次数。

算法流程图只展示真正影响结果的步骤。伪代码优于大段工程代码。

### x.5 核心结果

**目标**：直接回答题目，并给出可执行、可比较的结果。

**至少包含**：

- 一个主结果表，给数值、单位、基线和条件；
- 一张主结果图，用于趋势、分布、机制、区间或权衡；
- 必要时给最终方案清单或决策表。

**结果段固定三问**：

1. 结果是什么；
2. 为什么出现；
3. 对题目决策意味着什么。

推荐写法：

```text
由表 x 可知，在[条件]下，[指标]为[数值和单位]，相较于[基线]变化[幅度]。
该变化主要由[模型机制/数据特征/约束]造成。
因此，本问建议[可执行决策]；当[边界条件]不满足时，不应外推该结论。
```

### x.6 模型检验

**目标**：证明结果不仅能算出，而且可信、可行、稳定。

按题型至少选一项主检验和一项补充检验：

| 题型 | 主检验 | 补充检验 |
|---|---|---|
| 统计推断 | 假设检验、残差诊断、置信区间 | 替代分布或稳健标准误 |
| 预测 | 时间外验证、MAE/RMSE/WAPE、区间覆盖 | 滚动窗口、基线模型、残差诊断 |
| 分类 | 混淆矩阵、F1、AUC、灵敏度/特异度 | 阈值敏感性、交叉验证、类别不平衡 |
| 评价排序 | 权重扰动、排名稳定性 | 替代权重或替代评价法 |
| 优化决策 | 约束审计、任务/物料守恒、基线比较 | 参数敏感性、压力场景、下界或最优间隙 |
| 随机/风险模型 | 多次重复、分位数或 CVaR | 分布假设改变、极端情景 |

收敛曲线只能证明算法停止，不能代替可行性、最优性和业务合理性检查。

### x.7 本问结论

**目标**：用一个短段落封闭本问，避免结论散落在图表中。

**必须写**：最重要的结果、验证结论、适用边界、交给下一问的输出。不要新开“本章小结”空页。

## 6. C 题常见任务的适配规则

### 6.1 数据规律与统计分析

按“数据口径 → 分布/相关/时序 → 统计检验 → 现实解释”组织。相关不等于因果，负相关不应直接解释为互补关系。所有显著性结论必须写清原假设和样本范围。

### 6.2 预测

必须写训练、验证和测试划分；时间序列禁止随机打乱。正文同时报告系统级指标和分组指标，给预测区间时需报告覆盖率和区间宽度。至少与一个简单基线同输出比较。

### 6.3 分类与判定

先解释标签和误判代价，再说明模型和阈值。不能只报告准确率；需给混淆矩阵、召回率或医学任务中的灵敏度/特异度，并检查类别不平衡和外部适用边界。

### 6.4 综合评价与排序

先说明指标方向、量纲和权重来源，再给评价模型。主观和客观权重可组合，但必须做权重敏感性或排名稳定性检查。最终输出不仅是排序，还应解释前列方案为何优、差距是否稳定。

### 6.5 优化、调度与决策

模型建立顺序固定为变量、目标、约束、边界和线性化。结果必须同时给目标值和硬约束审计。若使用启发式算法，至少提供基线、重复运行稳定性或局部精确下界中的一种，不能只给收敛图。

### 6.6 扩展问题或数据需求问题

不要只列“还需要更多数据”。应使用映射表：

```text
缺失因素 | 需要的数据 | 进入哪个模型参数/状态 | 影响哪个结论 | 获取方式
```

如果题面要求进一步建模，应给出更新后的变量、目标或状态转移，而不是停留在建议层面。

## 7. 图表与排版模板

### 7.1 图表职责

每张图表只承担一个主要论证角色。正文必须先引用再出现，并在图后解释。

**表格适合**：精确数值、方案清单、参数、指标、基线比较、约束审计。

**图件适合**：趋势、分布、相关结构、预测区间、权衡、敏感性、算法机制。

**统一规则**：

- 表题在上，图题在下；
- 表格优先三线表；
- 坐标轴和表头必须有单位；
- 图例说明对象，颜色之外提供线型、标记或纹理；
- 正文不放完整任务明细、全量矩阵或逐小时长表；
- 图件在最终栏宽下文字仍应可读；
- 不使用 Excel/绘图窗口截图。

### 7.2 图表后的解释模板

```text
图/表展示了什么对象和条件。
最重要的数值、趋势或分组差异是什么。
该现象由哪个数据特征、模型机制或约束造成。
它如何支持本问的结论或决策。
```

## 8. 模型评价与推广

### 8.1 模型优点

只写本文已经有证据支持的优点，例如：

- 将题面硬约束显式写入模型并完成逐项审计；
- 预测、优化和结果验证使用同一时间/单位口径；
- 通过基线、滚动验证或压力场景证明结论稳定；
- 子问题接口明确，前问输出能直接进入后问。

### 8.2 模型局限

每条局限写成“具体建模选择 → 影响 → 失效场景”，例如：

```text
模型将价格视为小时内常数，因此无法描述分钟级突发价格；在高频市场环境中可能低估调度收益。
```

### 8.3 可推广方向

改进必须可执行：增加何种数据、替换哪项假设、加入什么变量或约束、用什么检验判断改进有效。不要写“采用更先进算法”。

## 9. 参考文献

**表达目标**：支撑模型选择、参数来源、评价指标和领域解释，不充当装饰。

**要求**：

- 按正文首次出现顺序编号；
- 正文引用与文末条目一一对应；
- 中英文期刊、教材、标准和官方数据合理搭配；
- 模型选择段引用原始方法或权威综述；
- 参数和行业规则引用可追溯来源；
- 不引用无法核验的博客、百科或二次转载。

## 10. 附录与支撑包

### 10.1 论文附录

推荐结构：

```text
附录 A 运行环境与入口
附录 B 各问关键算法代码
附录 C 必要补充表和审计摘要
附录 D 完整附件文件索引
```

每段代码前写对应问题、功能、输入、输出和源码路径。论文只展示关键变量、目标、约束、求解和审计代码，完整源码进入支撑包。

### 10.2 支撑包

只提交：

- 可运行入口；
- 正式建模源码；
- 必要依赖说明；
- 小规模核心结果和审计摘要；
- 输入文件说明和校验值。

不提交历史实验、缓存、临时图件、论文工程、重复长表、个人路径和未使用程序。

## 11. 建议篇幅分配

优秀展示论文的核心正文约从 19 页到 45 页不等，不能把历史页数当作当届要求。应首先服从当届官方格式和页数规则。若当届没有硬上限，可按以下比例控制：

| 模块 | 建议比例 |
|---|---:|
| 摘要 | 1 页 |
| 问题重述 | 3%-5% |
| 问题分析 | 5%-8% |
| 假设、符号、数据处理 | 8%-12% |
| 各子问题 | 60%-70% |
| 模型评价与推广 | 4%-6% |
| 参考文献 | 1-2 页 |

默认以 18-24 页核心正文为组织目标；超出的长代码、全量结果和补充诊断移入附录或支撑包。不得通过缩小字号、压缩行距或堆叠多面板图强行压页。

## 12. 最终验收清单

### 结构

- 摘要完整位于第一页；
- 正文从问题重述开始，无目录；
- 问题分析、假设、符号和共同数据口径位于各问之前；
- 实际有几问就写几章，不保留空章；
- 每问形成目标、模型、求解、结果、检验和结论闭环；
- 模型评价、参考文献、附录顺序正确。

### 证据

- 摘要中的每个数字都能在正文定位；
- 每问至少一个清晰的量化结论；
- 每个主结果都有单位、基线或条件；
- 预测有时间外验证，分类有误判指标，优化有约束审计；
- 收敛图没有被当作唯一验证；
- 图表均被正文引用并解释。

### 表达

- 问题重述不复制题面；
- 问题分析解释“为什么”，不只是方法列表；
- 每个公式都有实际含义；
- 结果段回答“是什么、为什么、意味着什么”；
- 局限针对本文模型，不使用空泛套话；
- 不出现未经证据支持的“显著提升”“最优”“先进”。

### 排版与附件

- 无孤立标题、大面积空白、文字重叠和图表裁切；
- 图题在下、表题在上，单位和图例完整；
- 附录不重复符号表；
- 附录代码与支撑包源码一致；
- 支撑包不含缓存、历史候选、个人信息和无关材料。

## 13. 最终写作原则

国赛 C 题论文的稳定高质量结构可以概括为：

```text
先把题目说清楚
→ 再把选择模型的理由说清楚
→ 用公式和算法把问题变成可计算对象
→ 用结果图表直接回答题目
→ 用检验证明结果可信
→ 用局限和边界说明结论能用到哪里
```

模板固定的是论证责任，不是算法名称。任何章节只要不能帮助回答题目、解释结果或验证结论，就不应为了“结构完整”而保留。
