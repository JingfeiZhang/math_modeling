# 2026 国赛合规与交付辅助自检清单

> 本文件只做**辅助自检入口**，不维护第二套官方规则。
>
> 规则优先级统一为：
>
> `官方当年文件 > projects/cumcm/2026/contest.yaml > root workflow / audit > 本目录经验资料`
>
> 任何与本文件冲突的页数、AI、匿名、附件或提交要求，一律以上述高优先级来源为准。

## 一、赛前环境与项目状态

- [ ] 正式项目仍为正确的当前题目状态；赛前未开题时应保持 `problem: TBD`。
- [ ] 主工作台环境按根目录 `environment.yml` / workflow preflight 验证。
- [ ] 本目录 `requirements.txt` 只用于算法模板隔离验证，不覆盖主工作台环境。
- [ ] Python、MATLAB、XeLaTeX、PDF 工具、打包工具均通过实际 smoke；不要用历史“曾经通过”替代当前验证。
- [ ] `代码库/` 与培训资料只作为参考，不作为 Formal Evidence。

## 二、题意与建模闭环

- [ ] 每个子问题都有明确输入、输出、约束、主指标、单位和验证方式。
- [ ] 先建立同输出 baseline，再选择主模型；baseline 与主模型必须可直接比较。
- [ ] 主模型复杂度对应真实失败点或实际收益，不为了“高级”而升级。
- [ ] 固定输入没有误当决策变量，硬约束已显式进入模型和验证。
- [ ] 已设计人工可算、穷举或精确求解的小实例检查实现正确性。
- [ ] 预测/分类/优化/评价/机理等题型使用与任务匹配的专项验证。
- [ ] 最终结论包含适用边界、失败条件或风险说明，而不是只给单点结果。

## 三、数据与实验

- [ ] 原始数据来源、字段角色、单位、时间/空间粒度明确。
- [ ] 缺失值、异常值、标准化和特征工程均有题意或算法依据，不机械清洗。
- [ ] 无训练/验证泄漏、未来信息泄漏或分组泄漏。
- [ ] 至少完成 baseline comparison、task-specific validation、robustness/sensitivity、failure-case analysis 中与本题相关的高价值证据。
- [ ] 随机算法记录随机种子并进行必要的多种子复跑；确定性算法保留求解状态、轨迹或 gap 等证据。
- [ ] 图表和论文数字来自当前项目真实 artifact，并能追溯到 Formal / Paper Evidence。

## 四、AI 使用

- [ ] 实际 AI 使用与 `output/ai/raw_usage.jsonl` 内部记录一致。
- [ ] AI 参与内容经过人工审核、修改或验证；Formal 结果来自真实运行而不是 AI 文本。
- [ ] 使用 AI 时，正文参考文献前包含 AI 使用声明，并按当前官方要求生成 `AI工具使用详情.pdf`。
- [ ] 未使用 AI 时使用当前 policy 定义的无 AI 声明。
- [ ] 不把内部 raw log、完整聊天记录或未要求提交的内部证据打进 supporting archive。
- [ ] 不隐瞒对建模、代码、实验分析或论文写作有实质影响的 AI 使用阶段。

AI 细节格式和披露范围以：

- `config/ai_usage_policy.yaml`
- `projects/cumcm/2026/contest.yaml`
- 当前官方 AI 使用规定

为准，不以本目录历史模板为准。

## 五、论文与匿名性

- [ ] 摘要、正文、附录、附件成员、文件名和文档元数据均通过匿名性检查。
- [ ] 电子版首页、目录、正文页数、附录等按当前 `contest.yaml` 和官方格式规范执行。
- [ ] 摘要覆盖各问的对象、方法、关键结论、验证与边界；不要求固定字数或固定公式数量。
- [ ] 结果段优先写“结果 → baseline 比较 → 原因/机制 → 实际意义 → 边界”。
- [ ] 图、表、文字各自承担明确 reader question，避免装饰性绘图和表图重复。
- [ ] 参考文献真实可查，外部数据/材料按规则引用。

## 六、当前 2026 项目中已固化的关键提交约束

以下只作为当前项目配置的便捷摘要，最终仍以 `projects/cumcm/2026/contest.yaml` 为准：

- A4，页边距不少于 2.5 cm；
- 摘要最多 1 页；
- 正文主体最多 30 页；
- 附录不设当前项目硬页数上限；
- 论文与支撑材料分开提交，单文件大小按当前配置限制；
- 使用 AI 时需声明并提供 `AI工具使用详情.pdf`；
- 支撑材料包含实际使用的可运行源代码及需要提交的数据/中间材料；
- 题目原始附件按官方要求处理，不机械重复打包；
- 官方提交哈希使用 MD5，内部同时保留 SHA256 完整性检查。

不要把“摘要 800–1000 字”“正文 20–32 页”“每模型至少 10 个公式”“模型假设固定 4–6 条”等经验建议当成官方硬规则。

## 七、最终发布链

- [ ] `build` 前 AI disclosure 已刷新。
- [ ] `audit` 全部通过，尤其是规则、匿名、PDF、代码一致性、AI 和 package audit。
- [ ] `supporting.zip` 只来自项目 `src/submission` 白名单。
- [ ] 内部 AI raw log、缓存、临时目录、教学资料和 `代码库/` 不进入附件。
- [ ] 支撑压缩包由当前项目要求的压缩工具生成。
- [ ] `submission.pdf`、`supporting.zip`、MD5/SHA256 manifest 一致。
- [ ] `seal` 后不再修改发布文件；最终执行 `verify-release`。
