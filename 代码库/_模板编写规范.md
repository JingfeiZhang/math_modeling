# 参考算法模板编写规范

本规范适用于 `代码库/` 的离线示例。模板是 **study-only 的教学/原型资产**，不是当前赛题 Formal 实现。正式使用须遵守 `references/algorithm-sources/quality-standard.md`，在当前项目中重写接口、约束、验证和证据输出。

## 1. 模板目标

一个好模板应帮助快速回答：

- 这个算法的输入输出是什么？
- 什么数据/假设下可以使用？
- 最关键参数是什么？
- 失败时会怎样？
- 如何把它改造成当前项目里的候选模型？

模板不负责证明算法“优秀”，也不生成可直接写入论文的结果。

## 2. 文件头建议

```python
# -*- coding: utf-8 -*-
"""
<算法中文名> / <English name>

用途：2-4 行说明算法解决什么数学结构。
适用条件：数据规模、变量类型、关键假设。
不适用条件：至少列出 2 个常见反例。
输入：形状、单位/语义、顺序要求。
输出：数值、状态、诊断信息。
关键风险：泄漏/不可行/局部最优/尺度敏感等。
依赖：numpy / scipy / ...

注意：本文件为离线示例，示例数字和图不是比赛证据。
"""
```

## 3. 核心函数与演示分离

- 核心算法必须函数化；
- `if __name__ == '__main__':` 只做最小示例；
- 示例数据不得隐藏真实问题假设；
- 不在 import 时产生文件、图或训练任务；
- 关键错误应抛出可理解异常，不静默吞掉。

## 4. 输入输出合同

至少写清：

- 行/列/节点/时间步分别代表什么；
- 是否要求排序、非负、整数、平稳、标准化；
- 缺失值是否允许；
- 输出包含什么主结果和诊断；
- 求解失败/未收敛时如何表示。

不要用“传入数据即可”代替接口说明。

## 5. 示例数据

允许手写小数组或固定随机种子生成示例；禁止联网取数。示例目标是证明 API 能运行，而不是模拟竞赛真实数据。

若给出附件替换提示，应写成：

```text
阅读真实题面和数据字典
→ 在当前项目中建立数据接口
→ 复现本模板的核心逻辑
→ 使用项目自己的切分、指标、约束和验证
```

而不是“把示例数据换成附件就可以交卷”。

## 6. 随机性与可复现

- 随机模板必须接受 `seed/random_state`；
- 多次运行应能记录种子；
- 启发式算法输出至少包含可行性、目标值和轨迹/状态；
- 不用“某一次最好结果”代表整体表现。

## 7. 数据处理边界

预处理必须避免泄漏：

- scaler/encoder/imputer 只能在训练数据拟合；
- 时间序列保持时间顺序；
- target encoding 必须在折内或训练窗口内；
- 不为树模型机械标准化；
- 不为“正态好看”机械删除真实极端值。

## 8. 指标与 baseline

模板可以演示指标计算，但必须说明适用条件和方向。例如 MAPE 遇零值可能失真，Accuracy 在严重不平衡数据上可能误导。

算法 README 应给出合理 baseline；模板本身不应输出“优秀/良好/通过”这类无上下文评级。

## 9. 可视化

- 默认使用无界面 backend；
- 图形只展示一个明确关系；
- 轴标签包含变量与单位（若示例没有真实单位则明确为示例）；
- 禁止用装饰性 3D、彩虹色或复杂图形暗示模型更高级；
- 正式论文图必须由主工作台 Figure Contract 从真实 artifact 重新生成。

## 10. 兼容与依赖

模板兼容环境由 `代码库/requirements.txt` 管理，与根 `environment.yml` 隔离。不要为了让单个历史模板运行而修改主工作台依赖。

## 11. 不允许的静默回退

若首选算法缺少依赖，模板应：

- 明确报缺失依赖；或
- 显式返回“使用 fallback”的状态，并保证 fallback 语义相同且调用者知情。

不能把 LSTM、XGBoost 等静默替换成语义不同的 MLP/GBDT 后仍以原算法名称输出结果。

## 12. Formal 前必须重写

从模板选中方法后，在当前项目里重新完成：

```text
数据接口
+ 单位/变量角色
+ baseline
+ 约束/目标
+ 切分与随机种子
+ 题型专项验证
+ artifact 输出
+ 代码/数据/环境哈希
```

模板的价值是缩短原型时间，不是绕过建模判断。
