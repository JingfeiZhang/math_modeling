# 08 图论与网络模型

> 网络建模的首要风险不是最短路算法写错，而是**现实对象被错误映射成节点、边、方向、权重和容量**。

## 方法地图

Dijkstra、Floyd、MST、最大流/最小割等均为经典求解工具。是否使用由图结构和题面目标决定。

## 建模顺序

```text
现实对象
→ 节点定义
→ 边存在条件
→ 有向/无向
→ 权重/容量/成本单位
→ 简单网络手算或 baseline
→ 图算法
→ 路径/流量/瓶颈解释
```

## 关键检查

- 节点/边是否重复或遗漏；
- 距离、时间、成本是否混用；
- 方向是否与现实可达性一致；
- 不可达和缺失边如何表示；
- 最大流是否满足容量与流守恒；
- 地理坐标是否使用合理距离/投影；
- 动态网络是否被错误冻结成静态图。

## 算法边界

Dijkstra 要求非负边权；MST 解决连通成本而不是一般路径最优；最大流解决容量网络，不自动包含成本、时窗和车辆等复杂约束。

复杂结构应升级到 min-cost flow、time-expanded network、MILP 或动态网络模型，而不是强行套现有模板。

## 高价值验证

小网络手算、路径/流守恒、容量检查、边权扰动和关键节点/边敏感性。网络图本身只是展示，不能代替这些验证。

## 论文证据

优先展示最终路径/流量、瓶颈、方案前后指标和网络结构。节点过多时避免“毛线球”，应聚合、筛选关键流或改用矩阵/统计图。
