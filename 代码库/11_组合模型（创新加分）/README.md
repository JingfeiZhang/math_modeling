# 11 组合与混合模型

> 目录名中的“创新加分”是历史命名，不代表组合模型天然更高级或更容易得分。只有当单一模型存在**可解释、已验证的缺口**，并且不同组件承担互补职责时才考虑组合。

## 组合前必须回答

- 单一 baseline/main 到底失败在哪里？
- 每个组件负责解决什么不同问题？
- 组件之间的信息流和单位是否明确？
- 是否存在数据泄漏或重复使用验证集？
- 不组合方案是否已经足够？

## 组合类型

例如预测修正、预测→优化、全局→局部搜索、机制+数据驱动、ensemble 等。组合方式应由问题结构决定，不以名称创新为目标。

## 公平消融

组合模型通常应比较：

```text
component A
component B
simple/no-hybrid baseline
full hybrid
```

如果 full 只有微小或不稳定收益，优先保留简单组件。

## 验证

- 组件使用相同信息边界；
- 公平 baseline；
- 样本外/场景验证；
- 随机组合搜索的多种子；
- 关键接口敏感性；
- 复杂度收益是否稳定。

## 学术表达

创新点应写“新增了什么结构、解决了什么已识别问题、证据显示改善多少”，而不是“提出了 XX-XX 组合算法”。算法命名不能代替机制解释和消融。

## 回退

若无法用消融证明组件价值、接口解释不清或复现成本超过收益，则不进入 Formal。
