# 国赛评阅者视角：模型—证据—论文一致性

> 定位：P1–P5 的非 Formal 质量指南。用于帮助 Solver、Paper、Reviewer 从“评阅者会因什么降分”反推建模与论文决策。它不属于 reference-library 的 P1–P3 playbook 层，不是官方评分细则，也不是论文证据。
>
> 来源基础：培训资料《数学建模竞赛赛题选讲》《数学建模竞赛注意事项与经验分享》的评阅要点与案例讲解，经本项目学术质量标准筛选后提炼。

## 1. 评阅顺序：先审问题是否建对，再看算法是否漂亮

高质量答卷首先通过以下五问：

1. **目标定义是否真的对应题面交付？**
2. **关键约束是否完整，变量域是否正确？**
3. **模型、程序、结果三者是否一致？**
4. **方案是否先可行，再比较目标值或性能？**
5. **结论是否只覆盖实际验证过的数据、场景和搜索范围？**

推荐审查顺序：

```text
题意与目标
→ 变量/参数角色
→ 约束完整性
→ baseline / known-answer
→ 代码实现一致性
→ 可行性/样本外有效性
→ 比较与不确定性
→ 结论和边界
→ 表达与版面
```

## 2. Objective correctness

每个目标必须回答：

- 题面原句要求优化/评价的是什么？
- 目标变量或指标的单位是什么？
- 最大化/最小化方向是否正确？
- 是否遗漏次级目标、服务水平或风险要求？
- 若使用代理指标，为什么它能代表原目标？
- 多目标合成时，权重代表什么偏好？

若把原始目标换成代理量，至少给出数学等价、业务解释、题面/文献依据或决策不敏感验证之一；否则只能写“在该代理目标下”的结论。

## 3. Constraint completeness

优化/调度/资源配置题至少检查：

| 类别 | 典型内容 | 审查问题 |
|---|---|---|
| 容量 | 面积、库存、预算、资源上限 | 单位和时间尺度一致吗？ |
| 兼容性 | 地块—作物、任务—机器、人员—技能 | 是否遗漏禁止组合？ |
| 时间 | 季次、工期、先后关系、轮作 | 跨期耦合是否真实建模？ |
| 逻辑 | 若…则…、互斥、至少/至多 | 0-1 变量和 Big-M 是否合理？ |
| 服务 | 覆盖率、满足率、最低需求 | 是硬约束还是软目标？ |
| 风险 | 最坏场景、概率约束、波动 | 不确定性是否进入模型？ |
| 变量域 | 连续、整数、0-1、非负 | 求解器变量域与论文一致吗？ |

一个目标值很高但违反关键约束的方案不能参与“优劣比较”。

## 4. General model before instance result

历史赛题评阅经验的可迁移部分是：先给能描述一般情形的模型/算法，再把具体数据代入；不要只针对一个实例手工拼结果。

论文应让评阅者知道：

- 决策/状态变量的一般定义；
- 输入如何进入模型；
- 约束如何随规模扩展；
- 输出如何生成；
- 哪些地方只是本题特例。

## 5. Model ↔ Code ↔ Result parity

正式结果进入 claims 前，核对：

```text
论文变量与公式
↔ runner 变量、约束、目标
↔ 实际输入
↔ 结果表/图
↔ 最终结论
```

典型失败：

- 论文写 MILP，代码实际是启发式近似；
- 论文声称满足全部约束，代码漏实现某条逻辑约束；
- 论文指标与程序分母/窗口不同；
- 图和正文来自不同 run；
- 论文写 Pareto，实际上只跑了单一固定权重。

## 6. Feasibility first, objective second

统一顺序：

```text
solver status
→ feasibility audit
→ integrality / invariant audit
→ objective / utility comparison
→ optimality evidence
```

不同算法可行率不同，应先报告可行率/违反量，再比较目标。

## 7. Heuristic / metaheuristic 的额外证据责任

按可获得条件提供：

- 小规模精确解或枚举；
- LP relaxation / lower/upper bound；
- 多随机种子；
- 多实例或多场景；
- 可行率；
- 与简单规则/经典算法 baseline 比较；
- 计算预算和停止条件。

无 exact/gap 证据时，不写“全局最优”，而写“当前搜索预算下最优可行候选”或“近似 Pareto 解集”。

## 8. 信息边界：离线、在线、随机不能混写

### 确定性离线

决策前已知完整实例信息，可讨论 exact / gap / instance optimum。

### 在线 / 部分信息未知

策略必须按：

```text
当前可观察状态 → 决策规则 → 下一状态
```

不能偷看未来需求、天气、价格。

### 随机 / 不确定

必须先定义期望、分位数/尾部风险、最坏场景、服务水平或 regret 等评价标准，再比较策略。

## 9. 对抗性问题

每一问至少主动提出一个可能推翻结论的问题：

- 删掉关键指标，排名会变吗？
- 需求扰动后，方案仍可行吗？
- 时间切分后，预测优势还在吗？
- 换随机种子后，启发式结论还在吗？
- 代理目标换回业务指标，优势还在吗？
- 某边界假设失效后，claim 应降到什么范围？

能被轻易推翻的 claim，先缩小边界或补实验。

## 10. 论文快速阅读检查

如果评阅者只读：

- 摘要；
- 问题分析；
- 每问主模型定义；
- 核心表/图 caption；
- 每问结尾；
- 模型评价；

仍应能恢复：

```text
直接回答
→ 为什么这样建模
→ 关键定量结果
→ baseline/参考比较
→ 可信证据
→ 实际意义
→ 适用边界
```

## 11. 明确不吸收

不作为规则：

- 特定软件优先级；
- “多用算法就加分”；
- 固定 ±5%、±10% 灵敏度；
- 某历史实例中某方法“效果最好”向其他题泛化；
- 以模型、公式或图表数量衡量质量。
