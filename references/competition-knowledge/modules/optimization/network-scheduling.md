# 网络与排程决策模块

> **用途**：把“路、流、匹配、任务、时间窗、前后依赖”题面快速分流到网络模型或排程模型。仅服务 P1--P3 的模型方向和风险探针，不构成 Formal 证据。

## 0. 适用与排除

### 网络模型触发

- 对象天然是节点和边，流量沿边传递。
- 题面有供给/需求、连通、容量、路径、运输成本或一对一匹配。
- 输出是路径、边流量、分配量或匹配关系。

### 排程模型触发

- 对象是任务，带处理时间、释放时间、截止时间、机器/人员容量或前置关系。
- 输出是开始/完成时间、资源分配、任务顺序和迟到量。

### 排除或降阶信号

- 只有一条静态路径需求，却引入多商品流、时间扩展网络和复杂切换变量。
- 边成本依赖全局拥堵、流量乘积，或多个商品共享非线性容量，且未完成线性化。
- 任务处理时长、资源占用或评价指标无法观测；先做情景和假设，不宣称最优排程。

## 1. 题面到数学对象

| 题面句子 | 网络映射 | 排程映射 | 检查点 |
|---|---|---|---|
| 从 A 到 B 的最短/最便宜路线 | 有向边 `(i,j)`、流 `f_ij` | 不适用 | 边方向、是否可重复经过 |
| 节点有供给/需求 | `b_i`、流守恒 | 可视为任务释放/需求时点 | 总供需是否平衡 |
| 道路/管线容量 | `0<=f_ij<=u_ij` | 资源容量 `cap_{m,t}` | 容量单位和时间粒度 |
| 每个订单只能分配一次 | `x_{ij}` 或匹配二元变量 | `x_{i,m}` | 是否允许拆分/转运 |
| 任务不可重叠 | 不适用或转为时间扩展弧 | `s_i,c_i` 与顺序二元 `y_ijm` | 端点采用 `[s,c)` 还是闭区间 |
| A 必须在 B 前完成 | 不适用 | `s_B >= c_A + lag_AB` | 延迟是否允许 |
| 尽量少迟到/少切换 | 边成本或惩罚弧 | `T_i>=c_i-d_i, T_i>=0` | 迟到与未完成是否相同 |

## 2. 最小可运行版本

### 2.1 运输/最小费用流

令 `f_ij` 为边流量，`b_i` 为节点净供给：

\[
\min \sum_{(i,j)\in E} c_{ij}f_{ij},
\qquad 0\le f_{ij}\le u_{ij},
\]
\[
\sum_{j:(j,i)\in E}f_{ji}-\sum_{j:(i,j)\in E}f_{ij}=b_i.
\]

若是严格一对一匹配，增加 `x_ij in {0,1}` 以及每个供需点至多/恰好一次的约束。总供需不平衡时，显式加入虚拟源/汇和高惩罚缺口，不要静默修改需求。

### 2.2 单机/多机排程

令 `x_im` 表示任务 `i` 是否分配到机器 `m`，`s_i,c_i` 为开始/完成时间，`y_ijm` 表示在同一机器上 i 是否先于 j：

\[
\sum_m x_{im}=1,\qquad c_i=s_i+p_i,
\]
\[
s_j\ge c_i-M(1-y_{ijm}),\quad
s_i\ge c_j-My_{ijm},
\]
并用 `x_im+x_jm-1 <= y_ijm+y_jim` 等连接条件避免未同机任务触发不重叠约束。前置关系为 `s_j>=c_i+lag_ij`，迟到为 `T_i>=c_i-d_i,T_i>=0`。

## 3. 升级路径

### 网络 baseline

单源单汇用最短路或最大流；多供需用最近供给点/单位成本贪心运输；匹配用最近邻或成本排序。生成后必须重新审计容量、守恒和重复分配。

### 排程 baseline

按最早截止期（EDD）、最短处理时间（SPT）或关键路径优先，将任务插入最早可行位置；输出完整的开始/完成时间和资源分配，不只输出一个总时长。

### 升级顺序

1. 先做静态网络/规则排程，获得可行同输出基线。
2. 小规模用 LP/MILP 或专用最小费用流/CP-SAT 验证规则方案。
3. 有时间窗变化、交通/需求情景时，扩展为时间层网络或滚动排程。
4. 共享容量、切换成本或复杂逻辑导致精确模型超时，再做分解、滚动时域或有界局部搜索。

若规则 baseline 与精确解在核心指标和关键路径上近似，优先保留可解释规则，避免不必要的多层模型。

## 4. 关键诊断

### 门槛 A：守恒/覆盖

- 网络：逐节点净流残差、总供需差、孤立节点和边容量违反量。
- 排程：任务分配次数、未安排任务数、前置关系违反量和最大资源重叠。
- 任何缺口、未安排或虚拟边都必须作为显式结果。

### 门槛 B：时间/容量口径

- 网络记录边容量利用率、路径数、总流量和成本；检查边方向及成本是否重复计数。
- 排程记录 `[s,c)` 端点规则、最大迟到、机器利用率、切换时间是否包含。
- 单位不一致时，先回到数据字典，不调参数。

### 门槛 C：瓶颈扰动

- 删除或收紧一个高利用率边/资源，重算可行率和代价。
- 将关键处理时长、供需量或容量扰动 ±10%。
- 若方案只在单一图结构/时间点成立，结论降级为情景分析。

## 5. 失败回退

```text
网络不可行
├─ 查总供需、方向、断连和容量单位
├─ 题意允许延期/转运 → 加缺口或虚拟边并设置惩罚
└─ 不允许缺口 → 将断连作为业务结论，停止堆叠算法

网络模型过大
├─ 先求单商品/静态流
├─ 按时间或区域分解，固定边界流
└─ 仍超时 → 贪心路径 + 可行性修复 + 成本上界

排程不可行
├─ 查端点、释放时间、前置环和机器容量
├─ 若允许延期 → 引入迟到/未完成惩罚变量
└─ 若任务必须完成 → 用关键路径或规则排程给可行解

规则与精确解差距大
└─ 保留精确模型，增加一次瓶颈/切换成本探针；不要只调优先级权重
```

## 6. 最小实验序列

1. 网络题在小图上对照一条手工最短路/运输分配；排程题用 10--20 个任务对照 EDD、SPT 和关键路径。
2. 删除或收紧一个瓶颈边/资源，检查可行率、成本/迟到和替代路径或关键任务。
3. 只有规则和精确模型差异会改变结论时，才引入时间扩展、共享容量或局部搜索。

## 7. 记录字段

记录 `problem_id`、`question_id`、`run_id`、节点/边或任务清单哈希、时间单位、容量/处理时长来源、边方向、端点约定、baseline 规则、求解器/版本、固定种子（如有）、总成本/总时长/迟到、守恒或覆盖残差、容量利用率、资源利用率、断连/未安排数量、瓶颈扰动、运行时间、状态、回退原因和输出路径。若使用教材卡，只保留 `source_id`、章节和“用于选型/探针”的用途。

## 8. 论文交接边界

可交接：图/任务抽象、变量和约束、时间端点、baseline 可比性、瓶颈诊断、规则与精确模型的选择理由。

不可交接：教材示例图或数据、未经本项目验证的复杂度/最优性断言、规则方案的手工数字。正式路径、排程表、成本和图件必须追溯到 Formal 或合格 Paper Evidence；网络/排程模块本身不能冻结 claims。
