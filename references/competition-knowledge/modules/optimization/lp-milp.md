# LP/MILP 决策模块

> **用途**：P1--P3 的模型筛选、变量映射和最小风险探针。本文档是教材速查层的自写决策辅助，不是 Formal 证据、论文引文或正式模型结论。

## 0. 适用与排除

### 触发信号

- 题目要求在有限资源、预算、容量或时间窗下分配数量。
- 决策包含“是否建设/启用/选择”“整批订购”“最多选若干个”等不可分割动作。
- 收益、成本、消耗和容量在题目精度下可写成变量的线性组合。

### 排除或降阶信号

- 乘积、比值、平方或阈值效应本身就是结论核心，且没有可信的线性化区间。
- 整数变量只是把连续结果四舍五入，而不是业务动作；先保留 LP。
- 逻辑约束的上界只能凭经验猜 Big-M。
- 模型需要大量历史状态但没有阶段结构；不要强行用 MILP 替代动态模型。

**决策顺序**：先写 LP 松弛并检查可行性，确认整数/逻辑确实影响方案后再升级 MILP；先求一个可行解，再谈最优性。

## 1. 题面语句到变量和约束

| 题面语句 | 变量映射 | 约束映射 | 必须追问 |
|---|---|---|---|
| 生产/采购数量 | `x[p,t] >= 0` | 产能、库存、需求平衡 | 是否允许拆分、欠交或延期 |
| 选择一个方案 | `z[k] in {0,1}` | `sum(z)=1` 或 `<=1` | 空方案是否允许 |
| 启用设备后才能产出 | 连续 `x`、开关 `z` | `x <= U*z` | `U` 的业务上界是什么 |
| 至少/至多选若干 | 二元 `z` | `L <= sum(z) <= U` | “至少”是否硬约束 |
| A 或 B，不能同时 | 二元 `zA,zB` | `zA+zB<=1` | 是否存在 A/B 都不选 |
| 整批/批量 | 整数或批次数 `q` | `x = batch*q` | 批量是否固定、是否可有尾批 |
| 总成本最小 | `x,z` | 线性成本项 | 固定费是否只在启用时发生 |

单位必须在变量名或数据字典中明确，例如“件/日”“吨/月”“元/批”。所有约束的左右两侧应在同一单位和同一时间粒度。

## 2. 最小可运行版本

设 `x` 为连续数量，`z` 为开关，`y` 为可选的逻辑辅助变量：

\[
\min_{x,z,y}\; c^Tx+f^Tz+h^Ty
\]
\[
Ax+By\le b,\qquad A_{eq}x+B_{eq}y=d,
\]
\[
\ell\le x\le u,\qquad z\in\{0,1\}^m.
\]

开关和数量的连接使用业务上界而非任意大数：

\[
0\le x_j\le U_jz_k.
\]

若需要“超过阈值才计费”，引入分段变量或二元区间选择；先在一个有业务意义的区间内做分段线性近似，并保留近似误差检查。不要直接把非线性项删掉。

### 最小可运行实现

1. 统一输入表：变量、单位、上下界、成本、资源系数、约束来源。
2. 写 LP 松弛，输出一组连续解和最大约束残差。
3. 只对真正不可分割的变量设置整数/二元类型。
4. 保存求解状态、目标分解、约束检查和原始输出，不从日志手抄数字。

## 3. 升级路径

### Baseline（P2）

按容量比例、单位收益排序或最近可行分配生成方案；若违反约束，使用最小代价修复。Baseline 必须输出与主模型同类的 `x/z` 决策，并使用同一个目标函数和约束审计。

### 升级顺序（P3）

1. **LP**：验证线性假设、可行域和资源瓶颈。
2. **MILP**：仅加入必要的整数、开关和逻辑约束。
3. **分段线性化**：对少数关键非线性项设置可解释区间。
4. **分解或滚动求解**：规模超出预算时按时间、区域或资源块分解。
5. **有界启发式**：只有精确模型在时间预算内不能得到可行解时启用；保留当前最好可行解、下界/上界和停止原因。

若 LP 已给出整数解且 MILP 没有改善目标或逻辑结论，保留 LP 作为主模型，避免为“模型更复杂”而升级。

## 4. 关键诊断

### 门槛 A：可行性与尺度

- 记录求解状态、最大约束违反量、变量上下界命中率。
- 不可行时按约束组逐步禁用或放宽，定位冲突；不得直接删除约束。
- 系数跨越多个数量级时先缩放，再比较求解结果。

### 门槛 B：整数价值与求解进展

- 记录 LP 松弛目标 `z_lp`、当前整数解 `z_int`、相对间隙和运行时间。
- gap 长时间不降时检查 Big-M、对称变量和重复逻辑；不能把超时的 incumbent 写成证明最优。
- 若整数化只改变小数尾数且不改变决策层结论，降回 LP。

### 门槛 C：扰动下的结构稳定

- 对需求、容量、成本和关键上界做至少一次 ±10% 扰动。
- 比较可行率、目标变化、启用集合和主要资源瓶颈。
- 方案若只在单一参数点成立，结论应降级为情景结果，不冻结为普遍规律。

## 5. 失败回退

```text
LP 不可行
├─ 检查单位/上下界/守恒和重复约束
├─ 定位冲突约束组
└─ 若题意允许延期或缺口，加入有惩罚的缺口变量并标注

MILP 超时
├─ 保留最好可行解和 gap
├─ 收紧由业务推导的 U、消除对称、缩小时间/区域块
└─ 仍超时 → LP/分解/规则 baseline，报告最优性未知

整数结果不稳定
├─ 检查批量、阈值和固定费是否真实存在
├─ 做 LP 与 MILP 对照
└─ 结论仅保留对可行性和数量级稳定的部分

非线性主导结论
└─ 回退到分段线性化或 NLP 探针，不伪装成线性最优
```

## 6. 最小实验序列

1. 取 10% 规模，运行贪心 baseline、LP 和必要的 MILP；三者必须输出同类分配对象。
2. 对一个需求/容量参数做 ±10% 扰动，检查可行性、目标和启用集合。
3. 只有 LP 与 MILP 的决策差异会改变题目结论时，才扩大规模或继续线性化。

每次 Scratch/Candidate 至少记录：`problem_id`、`question_id`、`run_id`、输入文件哈希、代码哈希、求解器/版本、随机种子（如有）、模型版本、变量类型、Big-M/上界来源、目标和单位、约束组清单、状态、运行时间、目标分解、最大违反量、LP/MILP gap、扰动方案、是否可复现、停止/回退原因。教材来源只记录 `source_id` 和用途，不写入正式 claims。

## 8. 论文交接边界

可以交接：变量含义、约束来源、线性化假设、baseline 定义、求解器与停止准则、可行性和敏感性设计。

不能直接交接：教材中的示例数值、未核验页码、某个通用算法“保证有效”的表述、Scratch 结果和超时解的最优性结论。论文中的正式数字、图表和主张必须来自 Formal 或合格 Paper Evidence；教材卡最多作为模型方向和风险探针记录。
