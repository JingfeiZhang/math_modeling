# 国赛高质量建模战术手册

本手册只解决一个问题：**如何在有限时间内把“能跑的模型”提升为“与题意高度匹配、验证充分、结论有价值的模型”**。它不是新的门禁系统，也不要求增加额外文件；它改变的是 P1–P3 的默认建模策略。

## 一、总原则：复杂度必须购买到真实收益

默认路线不是“先找最先进算法”，而是：

```text
题意结构
→ 最简单可比较 baseline
→ 结构匹配的经典主模型
→ 找出主模型真实失败点
→ 只针对失败点升级一次
→ 用验证决定保留还是回退
```

复杂模型只有在至少满足一项时才值得保留：

1. 明显改善题面主指标，而不是替代指标；
2. 修复 baseline 或简单模型已经暴露的结构性缺陷；
3. 显著降低不可行率、尾部风险或关键场景损失；
4. 能表达题目必须回答、而简单模型无法表达的机制或约束；
5. 在相近效果下带来明显更好的解释性、稳定性或决策价值。

若复杂度只带来更长公式、更难调参或更漂亮的模型名称，应回退。

## 二、P1：先找数学结构，不急着命名算法

每问先回答六个问题：

- **对象**：真正被预测、评价、优化或解释的对象是什么？
- **输出**：评委最终希望看到一个数、一组方案、一条曲线、一个排序还是一组决策规则？
- **约束**：哪些条件绝不能违反？哪些只是偏好？
- **信息结构**：什么在决策前已知，什么事后才知道？
- **耦合**：本问与前后问共享哪些变量、参数和口径？
- **失败代价**：模型最可能在哪类场景下给出错误或无用答案？

再把问题映射到数学结构：预测、分类、评价排序、确定性优化、随机/鲁棒优化、动力学/机理、仿真、网络、博弈或混合问题。

### P1 输出应形成“模型候选梯子”

每问最多保留四层：

```text
Baseline      最简单、同输出、能解释
Main          最匹配题面结构的主模型
Challenger    只验证一个关键替代解释或复杂度收益
Fallback      比主模型简单、比赛后期可稳定交付
```

不要同时维护五六个主模型。

## 三、P2：baseline 不只是验代码，而是建立论文比较坐标

高质量 baseline 应满足：

- 与主模型**输出相同**；
- 与题面主指标**评价口径相同**；
- 足够简单，能解释为什么它是合理下限或朴素方案；
- 能暴露主模型究竟改善了哪一部分。

常用 baseline：

- 预测：均值、上一期、季节朴素、简单线性/指数平滑；
- 分类：多数类、简单阈值、逻辑回归；
- 排序评价：等权、单指标排序、简单线性加权；
- 优化：贪心、规则方案、小规模枚举、线性松弛；
- 机理：最简守恒/线性近似、无反馈模型；
- 仿真：解析近似、确定性均值场景。

如果主模型不能稳定超过一个合理 baseline，先查问题定义、数据泄漏、指标或约束，不要继续堆模型。

## 四、P3a：选择模型时看“适配度”，不是只看分数

主模型选择按以下顺序思考，不需要机械打分：

1. **结构适配**：模型是否直接表达题目的时间性、空间性、约束、非线性、离散性或不确定性？
2. **信息合法**：是否只使用决策时点可获得的信息？
3. **可验证性**：是否能设计样本外、小实例、边界条件或压力场景验证？
4. **边际收益**：相比 baseline 的提升是否足够稳定、足够有意义？
5. **解释性**：能否说明“为什么得到这个结果”？
6. **计算风险**：剩余比赛时间内是否可重复运行和调参？
7. **论文价值**：能否用清晰公式、表图和结论讲明白，而不是只能描述黑盒过程？

### 升级模型的正确方式

先写出简单模型失败点，例如：

- 残差存在明显季节性；
- 线性模型对高峰段系统性低估；
- 名义优化在需求扰动下频繁不可行；
- 等权评价对指标冗余过度敏感；
- 机理模型在边界区域出现系统偏差。

然后让升级模型只解决这一点。这样论文中的模型选择就自然变成：

> 由于 baseline 在 X 场景出现 Y 缺陷，因此引入 Z 结构；该结构使主指标/可行性/稳定性得到实际改善。

而不是“因为某算法先进，所以采用”。

## 五、P3b：实验设计要回答“模型真的更好吗”

优先做高信息量实验，不做无目的调参。

### 预测 / 时间序列

核心证据优先级：

```text
时间外/滚动验证
> 同输出 baseline
> 误差分布与高代价区间
> 区间覆盖或校准
> 特征/模块增益
```

优先检查：泄漏、趋势漂移、分组差异、极端时段、预测 horizon 退化。

### 分类

核心证据：基率、混淆矩阵、Precision/Recall/F1、PR-AUC、阈值敏感性和校准。类别不平衡时不要用 Accuracy 主导结论。

### 优化 / 调度

核心证据优先级：

```text
可行性
> 同输出规则/baseline
> 小规模精确解或下界/gap
> 敏感性与压力情景
> 多种子/运行稳定性
```

启发式算法最重要的是证明方案“好且可信”，不是证明算法名字高级。

### 多目标

至少展示真正不同偏好的方案或非支配方案；报告目标之间的边际交换。固定一个权重只能解释为“该偏好下的方案”。

### 评价 / 排序

重点检查：指标方向、标准化、共线/冗余、权重来源、权重扰动、删项稳定性。若小幅调权就导致排名剧烈变化，应把“不稳定”本身写进结论。

### 机理 / 动力学

核心证据：量纲、守恒、初始条件、边界、参数可辨识性、校准与验证分离、极限情形和敏感性。不要只报告拟合优度。

### 仿真

区分预热期、稳态/瞬态、随机重复和置信区间；设计实验要覆盖真正影响决策的因素，而不是只画多条曲线。

## 六、消融和敏感性：只做能改变判断的

消融不是为了凑表格。只问：

> 去掉这个模块后，模型在我们声称解决的那个问题上是否明显变差？

敏感性也不是机械地每个参数 ±10%。优先扰动：

- 题面没有精确给定但影响大的参数；
- 数据估计误差大的参数；
- 会改变方案可行性或排序的参数；
- 结论最依赖的阈值、权重和成本。

若结果对关键参数高度敏感，应把敏感区间转化为实际决策边界，而不是隐藏。

## 七、跨问题质量：整篇论文要像一个模型系统

多问赛题常见失分点不是单问模型差，而是各问像独立作业。

优先复用：

- 数据口径和时间/空间粒度；
- 核心符号；
- 前问输出到后问输入；
- 同一评价指标；
- 共同不确定性情景；
- 共同约束或状态变量。

如果 Q1 的输出进入 Q2，应明确说明误差如何传播。若前问只提供辅助分析，不应为了“串联”强行让后问依赖它。

## 八、结果解释：把数学结果转成比赛答案

每个主要结果至少回答：

```text
结果是什么？
比 baseline 好多少/差多少？
为什么会形成这个结果？
对题目背景意味着什么？
在什么条件下可能失效？
```

推荐句式逻辑，不要求机械套句：

> 在 X 条件下，模型得到 Y；相较 baseline，Z 指标改善/变化 A。该变化主要来自 B 机制，因此对实际决策意味着 C；当 D 超出当前验证范围时，结论不再外推。

## 九、时间和 Token 使用原则

AI 深度参与时，优先让 AI 做高价值工作：

- 生成 2–3 个结构不同的候选方案；
- 主动找反例、失败场景和隐藏假设；
- 检查公式、变量角色和代码实现；
- 设计最有区分度的实验；
- 解释异常结果；
- 将复杂结果压缩成可验证结论。

避免消耗大量 token 做：

- 十几个模型的百科式介绍；
- 没有数据支持的长篇文献综述；
- 反复润色尚未冻结的文字；
- 对无关参数进行大规模自动调参；
- 为了“高级感”不停改模型名称和结构。

## 十、停止规则

出现以下情况时应停止升级模型并转向 Formal 与论文：

- 主模型稳定优于合理 baseline，且提升能被解释；
- 关键硬约束、样本外/压力场景和主要失败风险已有证据；
- challenger 没有推翻主模型结论；
- 新增复杂度只能带来微小或不稳定改善；
- 剩余时间继续调模的边际收益低于完善论文、验证和结果解释。

高水平国赛建模的目标不是“最复杂”，而是**题意正确、模型合适、实验有区分度、结果可信且能形成清晰决策结论**。
