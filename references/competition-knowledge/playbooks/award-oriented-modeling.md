# 国赛高质量建模战术手册

本手册只解决一个问题：**如何在有限时间内把“能跑的模型”提升为“与题意高度匹配、验证充分、结论有价值的模型”**。它不是新的门禁系统，也不要求增加额外文件；它改变的是 P1–P3 的默认建模策略。

细化决策由四份配套手册负责：

- `data-and-feature-quality.md`：哪些数据处理和特征工程真正必要；
- `algorithm-routing-quality.md`：不同数学结构优先跑什么算法、何时升级；
- `experiment-design-quality.md`：哪些实验的信息增益最高、何时停止；
- `visual-evidence-quality.md`：Formal 后什么结果应该画、画成什么、如何服务论文论证。

## 一、总原则：复杂度必须购买到真实收益

默认路线不是“先找最先进算法”，而是：

```text
题意结构
→ 识别会改变结论的数据风险
→ 最简单可比较 baseline
→ 结构匹配的经典主模型
→ 找出主模型真实失败点
→ 只针对失败点升级一次
→ 用高信息量实验决定保留还是回退
→ 把 Formal 结果转成读者可理解的证据
```

复杂模型只有在至少满足一项时才值得保留：

1. 明显改善题面主指标，而不是替代指标；
2. 修复 baseline 或简单模型已经暴露的结构性缺陷；
3. 显著降低不可行率、尾部风险或关键场景损失；
4. 能表达题目必须回答、而简单模型无法表达的机制或约束；
5. 在相近效果下带来明显更好的解释性、稳定性或决策价值。

若复杂度只带来更长公式、更难调参或更漂亮的模型名称，应回退。

## 二、P1：先找数学结构，不急着命名算法

每问先回答：

- **对象**：真正被预测、评价、优化或解释的对象是什么？
- **输出**：评委最终希望看到一个数、一组方案、一条曲线、一个排序还是一组决策规则？
- **变量域**：连续、整数、0-1、类别、状态变量分别是什么？
- **目标**：模型实际优化/评价的量是否就是题面真正要求的目标？
- **约束**：哪些条件绝不能违反？哪些只是偏好？是否有遗漏的容量、兼容、守恒、时序、逻辑或变量域条件？
- **关系结构**：时间、空间、网络、层级、动态、非线性或随机性在哪里？
- **信息结构**：什么在决策前已知，什么事后才知道？
- **耦合**：本问与前后问共享哪些变量、参数和口径？
- **失败代价**：模型最可能在哪类场景下给出错误或无用答案？

再把问题映射到预测、分类、评价排序、聚类、确定性优化、随机/鲁棒优化、动力学/机理、仿真、网络、博弈或混合问题。

### 2.1 Formulation 五联检

在进入算法比较前，用下面五个问题检查问题表示本身：

```text
题面要求
↔ Objective / output
↔ Variables / constraints / information timing
↔ Code input-output
↔ Validation / final claim
```

若其中任一环节对不上，优先修 formulation，而不是换算法。尤其注意：

- 代理指标不能无说明替代题面目标；
- 题面硬约束不能留到求解后人工修补；
- 事后信息不能提前进入决策；
- 程序输出必须能一一映射回论文中的变量和方案；
- 验证必须检查我们真正声称的结论，而不是方便计算的副指标。

### P1 输出应形成“模型候选梯子”

每问默认最多保留四层：

```text
Baseline      最简单、同输出、能解释
Main          最匹配题面结构的主模型
Challenger    只验证一个关键替代解释或复杂度收益
Fallback      比主模型简单、比赛后期可稳定交付
```

不要同时维护五六个主模型。

## 三、P1/P2：数据处理先问“会不会改变结论”

不要机械执行“均值填补 → 3σ删异常 → 全部标准化 → 批量造特征”。优先识别：

- 数据错误、单位冲突、重复和主键错位；
- 特殊值/状态的真实生成语义；
- 时间/空间/组内依赖及未来信息泄漏；
- 偏态、重尾、零膨胀、异方差、类别不平衡；
- 特征在真实决策时点是否可获得。

特征工程按“题面原生变量 → 有现实含义派生量 → 纯算法增强”三级推进。只有已观察到简单输入的具体不足时才进入高阶交互、大量 lag、PCA/embedding 等算法增强。

详细规则见 `data-and-feature-quality.md`。

## 四、P2：baseline 不只是验代码，而是建立论文比较坐标

高质量 baseline 应满足：

- 与主模型**输出相同**；
- 与题面主指标**评价口径相同**；
- 足够简单，能解释为什么它是合理下限或朴素方案；
- 能暴露主模型究竟改善了哪一部分。

常用 baseline：

- 预测：均值、上一期、季节朴素、简单线性/指数平滑；
- 分类：多数类、简单阈值、逻辑回归；
- 排序评价：等权、单指标排序、简单线性加权；
- 聚类：必要尺度处理后的 KMeans；
- 优化：贪心、规则方案、小规模枚举、线性松弛；
- 机理：最简守恒/线性近似、无反馈模型；
- 仿真：解析近似、确定性均值场景。

如果主模型不能稳定超过一个合理 baseline，先查问题定义、数据泄漏、指标或约束，不要继续堆模型。

## 五、P3a：选择模型时看“适配度”，不是只看分数

主模型选择按以下顺序思考，不需要机械打分：

1. **结构适配**：模型是否直接表达题目的时间性、空间性、约束、非线性、离散性或不确定性？
2. **信息合法**：是否只使用决策时点可获得的信息？
3. **可验证性**：是否能设计样本外、小实例、边界条件或压力场景验证？
4. **边际收益**：相比 baseline 的提升是否足够稳定、足够有意义？
5. **解释性**：能否说明“为什么得到这个结果”？
6. **计算风险**：剩余比赛时间内是否可重复运行和调参？
7. **论文价值**：能否用清晰公式、表图和结论讲明白，而不是只能描述黑盒过程？

算法的默认梯子和升级条件见 `algorithm-routing-quality.md`。核心原则是：能用结构清晰的精确/经典模型解决时，不为了“高级感”先上深度模型或元启发式。

### 升级模型的正确方式

先写出简单模型失败点，例如：

- 残差存在明显季节性；
- 线性模型对高峰段系统性低估；
- 名义优化在需求扰动下频繁不可行；
- 等权评价对指标冗余过度敏感；
- 机理模型在边界区域出现系统偏差。

然后让升级模型只解决这一点。升级后必须重新回答：原失败点是否被修复？主指标/可行性/稳定性是否得到稳定改善？

## 六、P3a/P3b：实验必须回答决策问题

默认实验组合：

```text
1 baseline comparison
+ 1 task-specific validation
+ 1 robustness/sensitivity
+ 1 failure-case analysis
```

只有模型确实由多个有明确作用的模块组成时才做消融；只有随机性影响结论时才增加多种子；超参数搜索必须晚于模型价值确认。

实验投入顺序：正确性 > baseline 增益 > 最可能失败点 > 稳健性 > 机制解释 > 精细调参。

详细题型实验策略见 `experiment-design-quality.md`。

## 七、题型专项证据

### 预测 / 时间序列

```text
时间外/滚动验证
> 同输出 baseline
> 误差按 horizon/time/group 分解
> 区间覆盖或校准
> 特征/模块增益
```

优先检查泄漏、趋势漂移、峰值和高代价区间。

如果预测/估计结果会进入后续决策，必须额外检查误差传播和最终决策指标；上游分数提高但下游方案无改善时，不把复杂度作为主要贡献。

### 分类

核心证据：基率、混淆矩阵、Precision/Recall/F1、PR-AUC、阈值敏感性和校准。类别不平衡时不要用 Accuracy 主导结论。

### 优化 / 调度

```text
formulation correctness
> feasibility
> 同输出规则/baseline
> 小规模精确解或下界/gap
> 压力场景与资源瓶颈
> 敏感性
> 多种子/运行稳定性
```

任何 objective 比较必须以同一硬约束下可行为前提。优化主图优先展示“方案和权衡”，收敛曲线仅作为辅助算法证据。

### 多目标

至少展示真正不同偏好的方案或非支配方案；固定一个权重只能解释为“该偏好下的方案”。推荐点必须有 knee、边际交换或实际偏好依据。

### 评价 / 排序

重点检查指标方向、标准化、冗余、权重来源、权重扰动、删项和 top-k 稳定性。排名不稳定本身就是重要结论。

### 聚类

除了内部指标，还要检查初始化/抽样稳定性和簇的实际可解释性；t-SNE/UMAP 不单独证明聚类正确。

### 机理 / 动力学

核心证据：量纲、守恒、初始条件、边界、参数可辨识性、校准与验证分离、极限情形和敏感性。

### 仿真

区分预热期、稳态/瞬态、随机重复和区间；实验因素围绕真正影响决策的变量。

## 八、消融和敏感性：只做能改变判断的

消融只问：去掉这个模块后，模型在我们声称解决的那个问题上是否明显变差？如果没有，应考虑删除模块或降低其论文地位。

敏感性优先扰动：

- 题面没有精确给定但影响大的参数；
- 数据估计误差大的参数；
- 会改变方案可行性或排序的参数；
- 结论最依赖的阈值、权重和成本。

若结果高度敏感，应把敏感区间转化为实际决策边界，而不是隐藏。

## 九、跨问题质量：整篇论文要像一个模型系统

多问赛题优先复用：

- 数据口径和时间/空间粒度；
- 核心符号；
- 前问输出到后问输入；
- 同一评价指标；
- 共同不确定性情景；
- 共同约束或状态变量。

真正的跨问接口至少明确：

```text
source field / meaning / unit / granularity
→ transformation or aggregation
→ target field / model role
→ uncertainty or error carried forward
```

如果 Q1 的输出进入 Q2，应明确误差如何传播，以及 Q1 模型变化是否真的改变 Q2 结论。若前问只提供辅助分析，不为“串联”强行让后问依赖它。

## 十、Formal 后：证据表达也是建模质量的一部分

Formal/claims 冻结后，不再为了图表重新改模型。可视化先回答 reader question，再决定 figure/table/text/none。

优先：

- 精确模型指标 → table 或 dot+interval；
- 预测一致性 → observed-vs-predicted / prediction interval；
- failure mode → error-by-group；
- 分布差异 → ECDF；
- 排名稳健 → rank-stability；
- 调度方案 → Gantt；
- 资源瓶颈 → resource-profile；
- 多目标权衡 → Pareto；
- 场景风险 → robustness matrix。

详细规则见 `visual-evidence-quality.md`。

## 十一、结果解释：把数学结果转成比赛答案

每个主要结果至少回答：

```text
结果是什么？
比 baseline 好多少/差多少？
为什么会形成这个结果？
对题目背景意味着什么？
在什么条件下可能失效？
```

推荐逻辑：结果 → 比较 → 原因 → 意义 → 边界。

同时保持：

```text
Model
↔ Code
↔ Result
↔ Paper
```

四者的变量含义、单位、方案定义和允许措辞一致。若论文中的结论无法回到程序输出和 Formal evidence，应先修证据链，不用文字补洞。

## 十二、时间和 Token 使用原则

AI 深度参与时，优先让 AI：

- 生成 2–3 个结构不同的候选方案；
- 主动找反例、失败场景和隐藏假设；
- 判断哪些数据处理真正会影响结论；
- 检查 formulation、公式、变量角色和代码实现；
- 设计最有区分度的实验；
- 解释异常结果；
- 从 Formal 结果中挑选最有论文价值的证据；
- 将复杂结果压缩成可验证结论。

避免大量 token 用于十几个模型百科、无数据支撑的长文献综述、冻结前反复润色、无关参数大规模调参和装饰性绘图。

## 十三、停止规则

出现以下情况时停止升级模型并转向 Formal 与论文：

- formulation、主指标和硬约束已闭合；
- 主模型稳定优于合理 baseline，且提升能被解释；
- 关键硬约束、样本外/压力场景和主要失败风险已有证据；
- challenger 没有推翻主模型结论；
- 新增复杂度只能带来微小或不稳定改善；
- 实验已经回答“正确、增益、失败、稳健、机制”五个核心问题；
- 若存在跨问接口，误差传播和最终决策价值已核清；
- 剩余时间继续调模的边际收益低于完善论文、验证和结果解释。

高水平国赛建模的目标不是“最复杂”，而是**题意正确、数据处理有依据、formulation 闭合、模型合适、实验有区分度、结果可信、图表能证明结论且最终能形成清晰决策答案**。
