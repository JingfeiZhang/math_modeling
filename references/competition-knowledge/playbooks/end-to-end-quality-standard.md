# CUMCM 端到端质量标准

本标准用于 P1–P6 的建模、实验、证据和论文阶段。它不增加新的 Gate、状态或审批；作用是让现有工作流在每一步都优先做**能改变结论、能提高可信度、能直接回答题目**的工作。

## 1. 总目标

高质量不是“模型多、算法新、图多、公式多”，而是同时满足：

1. **题意正确**：输出、单位、范围、时间/空间粒度与题面一致；
2. **结构匹配**：模型表达了题目的关键关系和约束；
3. **比较公平**：至少有同输出 baseline；
4. **验证针对风险**：检验最可能导致结论错误的环节；
5. **复杂度有收益**：复杂模型必须解决已观察到的失败点；
6. **证据可复核**：正式数字来自真实运行并可追溯；
7. **结论有边界**：不把局部、样本内或启发式结果写成全局事实；
8. **表达高密度**：图、表、正文各承担不同任务；
9. **跨问一致**：前问输出到后问输入的口径、单位和不确定性连续；
10. **及时停止**：证据已经足以回答题目时，把时间用于复核和论文，而不是继续堆模型。

## 2. 每问的最小思考链

在任何算法名称之前，依次回答：

```text
题面要求的最终交付是什么？
→ 数学对象、变量角色和关键约束是什么？
→ 哪些数据问题最可能让结论出错？
→ 最简单的同输出 baseline 是什么？
→ baseline 在哪里失败？
→ 哪个模型结构正好处理这个失败？
→ 什么实验最可能证伪这个模型？
→ Formal 后最重要的结论和边界是什么？
→ 评委需要图、表还是一句话才能相信它？
```

如果无法回答前一项，不应通过增加算法复杂度绕过问题。

## 3. P1：把题面变成可验证问题

### 必须做清楚

- 逐问识别研究对象、输入、输出、单位、时间/空间范围；
- 区分 `fixed / observed / decision / derived`；
- 识别数学结构：预测、分类、排序、优化、网络、机理、仿真或组合；
- 识别关键冲突、硬约束、信息可得时点和跨问接口；
- 识别 2–4 个最可能失败风险；
- 为每问提出一个最简单同输出 baseline；
- 设计至少一个可人工核验的小实例或不变量；
- 文献问题必须服务“参数、假设、模型选择或验证”，不做百科式综述。

### P1 反例检查

主动问：

- 是否把题面固定量误当决策变量？
- 是否遗漏题面要求的输出或副指标？
- 后问是否使用了前问在决策时点不可获得的信息？
- 是否在看到数据前就锁死某个熟悉算法？

### 停止条件

题面接口、数据口径、主要风险、baseline 候选和验证方向都明确后进入 P2；不要在 P1 提前做大量调参或论文润色。

## 4. P2：建立可信 baseline 和正确实现

### baseline 原则

baseline 必须：

- 与主模型产生同类别、同单位、同时间范围的输出；
- 足够简单，能解释“复杂模型究竟多买到了什么”；
- 不因故意弱化而成为稻草人。

### 优先验证

1. 已知答案小实例 / 穷举 / 手算；
2. 单位、分母、符号方向；
3. 数据切分与泄漏；
4. 硬约束和不变量；
5. baseline 的主指标。

### 停止条件

baseline 能运行、关键实现能被小实例复核、主指标口径正确后进入 P3a。此时无需追求最优参数。

## 5. P3a：主模型必须由失败点驱动

默认只维护：

```text
baseline + main + 一个有区分度的 challenger + 必要 fallback
```

新增复杂度前必须写出：

- baseline 的具体失败现象；
- 新结构针对哪个失败原因；
- 预期改善哪项指标/约束；
- 哪个实验能证明该复杂度值得保留。

### 模型选择优先级

```text
题意适配
> 信息合法与无泄漏
> 可验证性
> 样本外/场景稳定收益
> 可解释性与决策价值
> 计算与实现成本
> 算法新颖度
```

### 自我反驳

至少设计一个对主模型不友好的测试：峰值区间、极端场景、权重扰动、参数边界、不同随机种子、留出时间段或小规模精确解。

## 6. P3b：用信息增益决定继续还是停止

实验优先级：

```text
正确性
→ baseline 增益
→ 最可能失败点
→ 稳健性/不确定性
→ 机制解释
→ 精细调参
```

新增实验前问：

- 结果不同会不会改变主模型选择或 claim？
- 能否揭示新的失败边界？
- 是否只是把已知结论再画一遍？

若答案都是否，停止扩实验。

复杂模型仅有微小、波动性改善且解释/复现成本明显增加时，优先回退简单模型。

## 7. P4：Formal 冻结“可说什么”，而不只是数字

Formal 不只冻结最优结果，还要同时保留：

- baseline 与主模型比较；
- 关键假设和适用范围；
- 硬约束/可行性；
- 主要不确定性；
- 最差或失败场景；
- 随机算法的多种子结果或精确求解器状态/gap；
- 允许使用的结论措辞。

### 结论边界

- 启发式：写“近似解/有限预算下结果”，无最优性证据不写“全局最优”；
- 固定权重：写“给定偏好下方案”，不写“完整 Pareto 前沿”；
- 局部窗口：写“在所选窗口/场景中”，不外推全域；
- 相关/特征重要性：不自动写成因果关系；
- 样本内拟合：不写成样本外预测能力。

## 8. P5：把证据变成评委可读论证

每问推荐的论证顺序：

```text
题意与核心矛盾
→ 为什么选择当前模型
→ 最少必要公式/约束
→ 主结果
→ baseline 比较
→ 可信证据
→ 原因/机制
→ 实际意义
→ 失败边界
→ 直接回答题目
```

### 证据形式

- 精确数字比较 → Table；
- 趋势、分布、关系、权衡、空间、网络、调度 → Figure；
- 只有 1–3 个关键数字 → Text；
- 不能增加理解的信息 → None。

禁止把同一结果用“表 + 柱状图 + 正文逐项复述”重复三次。

## 9. P6：只修发布问题，不重新发明模型

P6 默认禁止：

- 无证据的新模型；
- 为了版面重新计算主指标；
- 为了语言更强修改 claim 边界；
- 无必要的大规模重构。

若发布审计发现的是证据错误，应回到受影响问题的最早证据层修复；不要在 P6 用文字掩盖。

## 10. 题型专项最低质量线

| 题型 | 最重要 baseline | 优先验证 | 典型失败风险 |
|---|---|---|---|
| 时间预测 | persistence / seasonal naive | rolling / out-of-time | 泄漏、峰值误差、区间失准 |
| 回归解释 | simple/regularized regression | residual + holdout | 共线性、异方差、伪解释 |
| 分类 | prevalence / logistic | PR、threshold、calibration | 类别不平衡、阈值错配 |
| 评价排序 | equal weight | weight/rank stability | 指标方向、权重任意性 |
| 聚类 | simple partition | stability + interpretability | 伪聚类、尺度敏感 |
| 优化 | rule/greedy/relaxation | feasibility + exact small case/gap | 不可行、局部解、错误约束 |
| 多目标 | single-objective/fixed preference | non-dominated coverage | 伪 Pareto、漏报代价 |
| 机理 | simple limiting case | dimension/boundary/conservation | 参数不可识别、边界错误 |
| 网络/调度 | simple route/rule | feasibility + bottleneck | 网络构造错误、容量遗漏 |

不是每题都要做所有检验；只做与主要失败风险匹配的检验。

## 11. 统一模型决策记录

在 Scratch/Candidate 思考中应能回答以下字段，即使不增加新的正式 schema：

```text
question_goal
baseline
main_model
challenger_or_reason_none
key_assumptions
data_risks
observed_baseline_failure
complexity_added_and_why
most_discriminating_test
result_of_test
failure_boundary
keep_or_fallback
next_high_value_action
```

这份信息用于提高决策质量，不要求作为新的提交附件。

## 12. Token / 计算预算原则

AI 和计算资源优先花在：

- 找反例和隐藏假设；
- 比较结构不同的 2–3 个候选；
- 设计能区分模型的实验；
- 调试公式、约束和实现；
- 解释异常结果；
- 压缩论文并提升证据密度。

避免花在：

- 枚举十几个算法；
- 无目的文献综述；
- 过早大规模超参搜索；
- 冻结前反复润色；
- 为“看起来高级”增加模型组件或图。

## 13. 最终质量判据

一个问题只有在评委能够快速回答以下六问时才算高质量闭环：

1. 题目要求什么？
2. 为什么选这个模型？
3. 相比简单方案改善了什么？
4. 为什么可信？
5. 结果对现实决策意味着什么？
6. 在什么条件下会失效？

如果只能回答“用了什么算法”，继续润色没有意义，应回到模型或证据层补强。
