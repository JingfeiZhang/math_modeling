# CUMCM 学术化建模与论文标准

本手册基于仓库对 2021–2025 官方展示 C 题论文的页面级精读，以及 `corpus/experience_report.md` 的跨题型证据总结。它迁移的是**高质量论证结构**，不是某篇论文的章节、算法、措辞或结果。

官方展示样本的稳定共性包括：摘要完成第一轮答题、前置章节统一变量和数据口径、各问形成独立证据闭环、图表承担明确证据职责、模型评价针对本文假设和边界而不是背教材优缺点。

## 1. 学术化的核心不是“写得像论文”，而是推理可审查

一段技术论证应尽量能回答：

```text
研究问题是什么？
→ 使用了什么信息？
→ 做了哪些必要假设？
→ 为什么该模型能表达关键结构？
→ 参数/变量如何定义与估计？
→ 哪些证据支持结果？
→ 还有哪些替代解释或失败边界？
```

如果只能回答“用了某算法并得到某数字”，学术闭环不足。

## 2. 问题分析：从题面语言到数学对象

高质量问题分析应给出：

- 研究对象与最终交付；
- 状态、观测、决策、参数和派生量；
- 时间/空间/群体层级；
- 约束、守恒、因果时序或信息可得性；
- 主要不确定性；
- 子问题之间的输入输出接口。

避免“问题一使用 A 算法，问题二使用 B 算法”的目录式分析。

## 3. 假设：少而必要，可验证或可讨论

每个关键假设至少说明：

1. 为什么需要；
2. 对应现实机制或数据事实；
3. 影响哪个公式/约束；
4. 如果不成立，结论会向什么方向变化；
5. 能否通过敏感性、替代模型或场景进行验证。

不要为了格式凑 5–8 条“忽略次要因素”式空假设。

## 4. 数据：不仅“清洗”，还要说明数据生成结构

至少交代：

- 观测单位与采样机制；
- 字段含义、单位和时间点；
- 缺失/异常/删样本的数量与理由；
- 多表连接关系；
- 训练、验证、预测或决策时的信息边界；
- 任何会产生选择偏差、泄漏或非独立性的结构。

数据处理必须能追溯到研究问题或模型要求。

## 5. 模型选择：提出候选、给理由、保留反证

学术化模型选择不是“哪个 RMSE 最小就选哪个”。应同时比较：

- 题意结构适配；
- 假设强弱；
- 预测/估计/优化性能；
- 可解释性；
- 稳定性与边界；
- 计算成本；
- 是否能与后续子问题自然衔接。

至少保留一个可解释 baseline。复杂模型必须解释其新增结构解决了什么已观察问题。

## 6. 参数估计与可辨识性

对于需要估计参数的模型，优先说明：

- 参数来源：题面给定、文献、拟合、优化还是专家设定；
- 目标函数或似然/损失；
- 参数范围与物理/业务限制；
- 多参数是否可能相互补偿；
- 是否存在多组参数产生近似相同输出；
- 参数变化是否改变主要结论。

不能把“优化器返回一组参数”自动等价为“参数具有真实物理含义”。

## 7. 统计推断：效应与不确定性优先于显著性标签

如果问题涉及统计关系，尽量报告：

```text
方向 + 效应量 + 区间 + 实际意义 + 假设/稳健性
```

而不是只报告 `p<0.05`。

相关性、Granger、特征重要性、SHAP 等都不自动识别因果。只有研究设计和识别假设支持时才使用因果措辞。

## 8. 预测：严格区分拟合与真正预测

预测能力必须来自决策时点之后的留出数据、滚动验证或其他无泄漏的样本外设计。模型选择、标准化、特征筛选和调参都必须位于训练边界内。

高质量预测结果不仅报告平均误差，还应说明：

- 哪些时间/群体/区间最难；
- 是否系统高估/低估；
- 极端值或峰值表现；
- 需要时的区间覆盖与宽度；
- 误差对后续决策的影响。

## 9. 优化：数学模型和求解算法分开论证

必须区分：

```text
决策模型是否正确
≠
求解器是否成功运行
```

先论证目标、变量和约束，再论证求解方法。推荐方案至少说明可行性、相对 baseline 的收益、代价/权衡和压力情景。

启发式结果应与小规模精确解、松弛界或可解释 baseline 建立质量坐标。

## 10. 机理与仿真：先守住物理/业务一致性

高质量机理模型优先检查：

- 量纲；
- 初值/边界；
- 守恒或容量；
- 极限情形；
- 参数可辨识性；
- 对关键机制假设的敏感性。

仿真图形逼真不能替代这些检查。

## 11. 不确定性：不要把一个点估计包装成确定事实

按题目需要区分：

- 观测噪声；
- 参数不确定性；
- 场景不确定性；
- 模型结构不确定性；
- 随机优化/算法随机性。

不要求所有问题都构造概率模型，但结论必须诚实反映主要不确定来源。

## 12. 验证：优先证伪，而不是自证

高质量验证应问：

> “如果我的模型是错的，最可能在哪里暴露？”

因此优先选择能攻击关键假设的实验，而不是机械堆误差、灵敏度、稳健性三节。

典型：

- 预测 → 时间外、峰值、分组误差；
- 排序 → 权重/删项稳定性；
- 优化 → 可行性、gap、小实例、压力场景；
- 机理 → 边界、守恒、极限、参数敏感性；
- 分类 → 阈值、PR、calibration、subgroup；
- 聚类 → 扰动稳定性与实际解释。

## 13. 图表：一张图完成一个论证动作

官方展示论文的高价值图表通常承担：数据结构、模型机制、主结果或模型检验四类任务。

每张正式图先写 reader question，再选择图型。图注至少说明对象、条件和主要比较；正文解释“结果意味着什么”，不逐像素复述曲线。

图的专业性来自正确编码、单位、不确定性和信息密度，不来自 3D、渐变、阴影或装饰。

## 14. 公式：强调模型语义，不堆推导

正文优先保留：

- 定义模型的核心关系；
- 目标函数；
- 关键约束；
- 状态转移；
- 评价指标；
- 必要的估计/变换。

每个关键公式后说明变量意义和现实解释。教科书可查的标准推导无需占大量正文。

## 15. 结果：数字必须进入比较和解释

核心结果使用：

```text
结果
→ 相对 baseline/参考的变化
→ 原因或机制
→ 决策/现实意义
→ 不确定性和边界
```

“较好、显著提升、鲁棒性强”必须有对应证据。

## 16. Discussion 思维进入每问，而不是只放最后

每问结果后至少有一句回答：

- 为什么出现该结果？
- 哪个假设/约束驱动？
- 对后问或实际决策有什么影响？
- 哪种条件下结论可能反转？

这比在最后统一写一页模板化“优缺点”更学术。

## 17. 摘要：像结构化研究摘要，不像目录

官方展示样本稳定采用按子问展开的高信息密度摘要。每问尽量包含：

```text
任务对象 + 方法/模型结构 + 关键定量结果 + 比较/验证 + 边界
```

摘要中的每个数字必须能在正文证据中定位。

## 18. 文献：只引用真正影响建模的来源

文献用于支持：

- 机制与理论依据；
- 参数范围；
- 方法选择；
- 评价标准；
- 外部事实或数据定义。

不为了“显得学术”堆几十篇引用。竞赛展示论文只能用于学习结构，不直接成为当前赛题的 Formal evidence。

## 19. 可复现性：论文简洁，证据链完整

正文不写工程流水账，但内部应完整保留：数据版本、代码、参数、seed、环境、run、图表源数据和 claim 映射。

学术化不是把这些哈希写满正文，而是让任何正式结论都能回到可复核证据。

## 20. 最终评审视角

理想情况下，评委只读：

```text
摘要
→ 问题分析
→ 关键模型定义
→ 主结果图/表
→ 每问结尾
→ 模型评价
```

仍能明确回答：研究问题、模型理由、关键结果、可信证据、现实意义和失败边界。

这就是本项目对“学术化高质量”的最低定义。
