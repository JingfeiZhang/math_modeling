# 先预测、再优化的赛题战术手册

> 用于需求、客流、价格或负荷预测后继续做库存、调度、资源分配的组合题。它只组织 P1-P3 的探索顺序，不提供 Formal 结果或论文证据。

## 触发与排除

触发：前一问要求预测未来量，后一问明确把预测量作为容量、需求、收益或成本参数；最终评价对象是决策，而非单纯预测精度。

排除：预测输出并不影响后续最优方案；题目已给出确定需求；未来数据不可获得但被当作已知特征；预测误差远大于决策容许区间且没有情景或补救动作。此时应直接做情景优化，或把预测限定为描述性输入。

## 输入输出合同

预测模块输入必须声明时间列、目标列、频率、预测起点、horizon、可用信息截点和分组。输出不能只有一列点预测，至少应包含：`time/group`、`point_forecast`、误差或区间定义、预测版本、训练截止时间。

优化模块必须明确读取哪个预测字段、单位如何转换、缺失预测如何处理、决策变量是否在不确定性实现前确定。最终输出是可执行方案、目标分解、约束审计和风险结果，不以预测模型内部指标替代决策指标。

## 分阶段行动

**P1**：画出 `历史数据 -> 预测 -> 参数转换 -> 优化 -> 方案评价` 数据流；逐字段标记预测时点是否可见。把预测误差可能影响的约束和目标单独列出。

**P2**：建立两组同输出 baseline。预测端跑持久性/季节朴素；决策端用历史均值或题面名义值生成规则方案。保存“朴素预测驱动的决策”作为端到端 baseline。

**P3a**：只选一个低复杂度预测候选和一个最窄优化模型。固定滚动验证起点；将每个起点的预测结果送入同一优化 runner，比较决策成本、违约率和方案变化。

**P3b**：只针对观察到的失败升级：残差季节性则修预测，约束违反集中在尾部则加情景/鲁棒保护，计算超时则简化优化。60% 时间附近锁定接口，不再同时更换预测与优化模型。

## baseline 与升级

```text
季节朴素预测 + 规则决策
  -> 低复杂度预测 + 确定性 LP/MILP
  -> 预测残差情景 + 情景复算
  -> 有依据的随机/鲁棒优化
```

升级判断使用端到端指标：即使预测 MAE 改善，如果方案成本、可行率或关键决策不改善，就不升级预测模型。反之，预测总体误差相近但在高代价时段更准确，可以保留，但必须用决策指标说明。

## 联合诊断

1. **时点与泄漏**：预测和优化都只读取决策时点可获得的信息；滚动起点之后的字段不得进入特征或名义参数。
2. **误差传播**：对预测值做残差重采样或分位扰动，记录可行率、目标、启用集合和库存/容量缺口；识别对方案最敏感的时段或分组。
3. **接口守恒**：检查聚合前后总量、单位、时间粒度和分组映射；预测总需求与优化需求行必须一一对应。
4. **价值分解**：分别比较朴素预测、改进预测、名义优化和稳健优化，避免把全部收益归因于某一模块。

## 停止与回退

- 复杂预测在多数滚动起点不优于季节朴素：回退朴素预测，保留区间。
- 预测误差变化不改变决策：固定简单预测，停止调参。
- 名义方案在压力情景频繁不可行：进入情景或鲁棒保护；若依据不足，只报告条件性方案。
- 优化计算超时：缩短滚动窗口、分区域/时间求解，或使用可行规则方案；不得把超时 incumbent 写成已证明最优。
- 预测接口或主指标改变：只重开受影响问题的 Candidate；本手册本身不能触发 Formal 冻结。

## Candidate 交接

至少交接：预测数据截点、baseline 与候选、滚动切分、逐 horizon 指标、预测输出 schema、优化输入映射、规则决策 baseline、候选方案、约束残差、误差传播场景、端到端指标、运行时间、采用/放弃理由。教材卡和本手册只记录为“探索参考”，不得进入 claims。

## 禁止事项

- 禁止使用全数据训练后再伪装成滚动预测。
- 禁止把未来真实需求直接喂给事前决策。
- 禁止只报告预测精度而不检查方案可行性。
- 禁止把教材阈值、示例数字或本手册的升级顺序写成论文证据。
- 禁止将本手册、原始 PDF 或内部资料卡加入 BibTeX、附件或 release。
