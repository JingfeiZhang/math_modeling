# 数据与特征质量手册

本手册不建立新的数据处理框架。它约束 Solver 在现有 runner 中如何判断“哪些处理真正必要”，目标是避免机械清洗、信息泄漏和无意义特征膨胀。

## 1. 总原则：先识别会改变结论的数据风险

所有处理先回答：不处理它，会让哪一个题面结论、指标或约束出错？如果无法回答，不默认处理。

优先排查四类风险：

1. **真实性**：重复、编码错误、不可能值、单位冲突、主键错配；
2. **结构性**：时间依赖、空间依赖、组内相关、重复测量、panel/层级结构；
3. **分布性**：偏态、重尾、零膨胀、异方差、类别不平衡；
4. **信息合法性**：未来信息、目标泄漏、决策时点后才可获得的变量、前后问口径漂移。

真实性问题优先修复；结构性问题优先改变验证和模型；分布问题优先考虑损失函数/分布假设；信息合法性问题必须先解决再比较模型。

### 1.1 特殊数值先解释“生成语义”，再决定清洗动作

`0`、负值、缺日期、状态切换、极低/极高值都不能先验地等同于“缺失”或“异常”。先问它由什么过程产生，例如：

```text
0
→ 真实为零？
→ 未观测/未发生？
→ 容量受限或供给中断？
→ 状态关闭/未启用？

负值
→ 合法反向流/退回/冲销？
→ 还是数据错误？
```

只有生成语义澄清后，才决定保留、修正、插补、加状态变量或删除。若不同语义会导致不同模型输入或不同结论，必须把该语义差异保留下来，而不是为了得到“干净数据”合并处理。

这一原则适用于交易、传感器、交通、能源、生产、库存、实验观测等数据，不依赖具体赛题背景。

## 2. 缺失值：先判断缺失机制，再决定处理

最低要求：报告字段级缺失比例、缺失是否集中于时间/区域/群体、处理后样本量变化。

选择顺序：

- 极少且近似随机：删除可以接受；
- 时间连续变量：仅在业务上可解释时做时间插值，并禁止跨越预测切分使用未来信息；
- 分组数据：可使用组内中位数/稳健统计，但必须保持验证折内拟合；
- 缺失本身含信息：增加 missing indicator；
- 高缺失率：优先重新审视该变量是否应进入主模型，而不是强行插补。

禁止：默认对所有数值变量均值填补；在完整数据上先插补再切训练/验证；对题面没有观测的关键量伪造值。

## 3. 异常值：区分错误、极端事件和模型失败区

异常点必须先分类：

- 数据错误：修正或删除，并记录规则；
- 合法极端事件：默认保留，它往往是压力场景和风险证据；
- 长尾但合理：优先 robust loss、log/Yeo-Johnson、分位数模型或稳健统计；
- 模型系统失效区域：保留并作为 failure-case 分析。

禁止机械使用 3σ/IQR 后删除全部异常点。若删点会显著改变结论，必须优先解释数据机制。

## 4. 标准化与变换必须服务算法

通常需要尺度处理：KNN、SVM、KMeans、PCA、正则回归、神经网络、基于距离或梯度敏感模型。

通常不因预测性能而必须标准化：决策树、随机森林、Boosting tree。若为解释或统一单位进行标准化，应写清目的。

变换只在存在明确问题时使用：

- 强正偏且乘法关系：log1p；
- 允许零/负值且强偏态：Yeo-Johnson；
- 计数：优先考虑 Poisson/Negative Binomial，而不是只做 log+OLS；
- 比例：考虑 logit/Beta 类建模及边界处理。

## 5. 时间、空间、分组数据的泄漏防护

时间数据：所有 lag、rolling、scaler、imputer 和特征选择只能使用当前预测时点之前的信息；验证优先 rolling/expanding window，禁止随机打乱替代时间外验证。

分组/panel：同一主体可能出现在多个时点时，按题意决定 group split 或 time split；不能让同一实体的未来状态泄漏到训练。

空间数据：坐标距离要根据尺度和投影判断；有空间自相关时优先空间阻断验证，而不是随机划分。

统一执行规则：任何会从数据估计参数的预处理器都遵循

```text
fit(reference/train)
→ freeze parameters
→ transform(validation/test/future)
```

包括 scaler、imputer、encoder、Box-Cox/Yeo-Johnson 参数、特征筛选、阈值和目标编码。不能因为它“只是预处理”就绕过验证边界。

## 6. 特征工程采用三级优先级

### Tier 1：题面原生变量

题目给定的状态、决策、约束和观测量优先保留，先证明它们能形成完整 baseline。

### Tier 2：有现实含义的派生量

优先构造可解释量，例如增长率、单位成本、容量利用率、库存覆盖、峰谷差、距离、密度、变化率、移动统计、风险暴露等。每个派生量必须能说明单位和现实意义。

### Tier 3：纯算法增强

多项式、大量交互、高阶 lag、PCA/embedding 等只在前两级暴露了明确不足后启用。

新增特征必须回答：它解决了哪个已观察到的错误模式？如果只使维度上升而没有稳定收益，应删除。

## 7. 特征选择：稳定性优先于单次重要度

不要按单次相关系数或单次 feature importance 机械删选。优先考虑：

- 题意必要性；
- 共线性和冗余；
- 不同验证折/时间窗下的重要度稳定性；
- 删除后对主指标与结论的影响；
- 决策时点是否可获得。

预测解释型问题应优先提供方向、效应大小和不确定性；树模型 importance 不能自动解释为因果影响。

### 7.1 外部数据只在能改变决策时优先接入

发现新的天气、成本、状态、地理、行为或其他外部数据时，先回答：

1. 它解决当前哪个失败点？
2. 在真实决策时点是否可获得？
3. 时间/空间/主体粒度能否合法对齐？
4. 是否引入未来信息或选择偏差？
5. 加入后会改变模型选择、验证结论或最终决策吗？

若只能丰富背景叙述、不能改变模型或证据，比赛期间不优先接入。

## 8. 数据处理的论文表达

正文只保留会改变模型输入或结论的处理：处理规则、比例、理由和影响。不要罗列“标准化、去噪、归一化”等未实际产生价值的步骤。

推荐结构：

> 数据在 X 字段存在 Y% 缺失，且缺失集中于 Z 场景；因此采用 A 方式在训练折内完成插补。该处理保持时间顺序，并通过 B 检查确认主结论未因插补方式改变。

## 9. 停止规则

当数据口径统一、关键数据生成语义已澄清、无关键泄漏、baseline 可运行，且新增清洗/特征只能带来微小或不稳定改善时，停止扩展预处理，转向模型与验证。
