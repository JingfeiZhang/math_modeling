# CUMCM 学术质量总标准

本标准用于 P1–P5 的内容质量控制，目标是把“能运行的数学建模方案”提升为“问题定义准确、数学结构清楚、证据充分、表达紧凑、边界诚实”的竞赛论文方案。

本标准根据仓库内 `corpus/reports/cumcm-c-writing-template-2021-2025.md` 对 2021–2025 年公开优秀/展示论文的结构与证据方式提炼，并结合当前项目的 Formal Evidence、claims 与 Figure Contract 使用。它不是官方评分细则，也不新增 Gate；当届官方规则始终优先。

## 1. 核心学术原则

高质量不是模型数量、算法名称、公式数量或图表数量的函数。优先级统一为：

```text
题意正确
→ 数学抽象正确
→ 数据与假设可信
→ baseline 可比较
→ 主模型结构匹配
→ 验证针对真实失败风险
→ 结论有定量证据
→ 结果有解释和决策价值
→ 边界与不确定性明确
→ 论文表达高信息密度
```

所有角色共同遵守六条原则：

1. **先回答题目，再讨论算法。** 模型必须服务题面交付，而不是反向让题目适配熟悉算法。
2. **先比较，再声称改进。** “更好”“更优”“更稳健”必须有同口径 reference/baseline。
3. **先尝试证伪，再增加复杂度。** 新模型先回答它修复了哪个已观察到的失败点。
4. **先给证据，再给形容词。** 没有数字、区间、可行性或专项验证支撑时，不写“准确、高效、鲁棒、先进”。
5. **先解释，再润色。** 结果段先回答“为什么”和“意味着什么”，语言优化不能替代缺失证据。
6. **先限定边界，再推广。** 训练范围、场景范围、权重范围、局部搜索范围和数据时段必须与措辞一致。

## 2. 优秀论文的最小闭环

每一问至少形成以下闭环：

```text
题面要求
→ 数学对象/决策目标
→ 输入、输出与单位
→ 关键假设与约束
→ baseline
→ 主模型及选择理由
→ 与题型匹配的验证
→ 主结果
→ baseline/参考比较
→ 原因或机制解释
→ 实际意义
→ 适用边界
→ 下一问接口（如有）
```

如果一问只能回答“用了什么算法”，而不能回答“最后交付什么、为什么可信、在哪里失效”，则内容质量尚未闭合。

## 3. P1：问题抽象质量

P1 不以列出算法为目标，而以建立正确的问题表示为目标。

### 3.1 需求映射

对题面每个动词建立交付映射：预测、评价、排序、优化、解释、设计、判断、仿真、建议等必须对应到明确输出。

至少写清：

- 研究对象与观测单位；
- fixed / observed / decision / derived 角色；
- 输入、输出、单位、时间/空间粒度；
- 题面主指标及其方向；
- 硬约束、软目标和业务边界；
- Q1–Qn 的上下游接口。

### 3.2 数学结构识别

不要停在“预测题/优化题”标签。继续识别：

- 连续、整数、0-1 或混合变量；
- 静态、动态、时序、空间、网络或 panel 结构；
- 线性、非线性、非凸、黑箱；
- 单目标、多目标、风险约束；
- 确定性、不确定性、场景或随机性；
- 监督、无监督、解释、预测或决策。

### 3.3 初始失败风险

在选模型前先列出最可能导致错误结论的 2–4 个风险，例如：

- 时间泄漏；
- 固定参数误当决策变量；
- 指标方向/分母错误；
- 单位或主键错位；
- 类别不平衡；
- 非凸局部解；
- 权重敏感；
- 参数不可辨识；
- 场景覆盖不足。

后续实验优先针对这些风险，而不是平均分配精力。

## 4. 数据与特征的学术质量

数据处理必须有“为什么”，并记录处理是否改变样本、分布、时间边界或解释含义。

### 4.1 先确认数据生成结构

至少判断：

- 观测单位；
- 时间/空间/主体层级；
- 缺失是否结构性；
- 重复是否真实重复测量；
- 异常是错误还是题目关心的极端事件；
- 决策时点能否获得该变量；
- 多表 join 是否改变行数。

### 4.2 预处理必须服务模型

- 树模型通常不因尺度差异需要标准化；
- KNN/SVM/KMeans/PCA/正则模型应检查尺度；
- 时间/组/空间数据的 imputer、scaler、encoder 只能在训练折内拟合；
- target encoding 必须防止目标泄漏；
- 异常值不因“难看”而删除；
- 变量变换要有分布、损失函数或机理理由。

### 4.3 特征工程三级优先级

1. **题面原生变量**：最高优先；
2. **现实含义明确的派生量**：增长率、单位成本、利用率、距离、峰谷差、库存覆盖等；
3. **纯算法增强特征**：高阶交互、大量 lag、embedding、PCA 等，只在已有失败证据时增加。

大量特征不是创新；能解释且稳定的少量关键特征通常更适合竞赛论文。

## 5. 假设、变量与公式闭环

高质量假设不是模板化“忽略次要因素”，而是对模型可解性和适用范围有实际影响的简化。

每个关键假设至少回答：

- 为什么可以做；
- 它影响哪个变量/约束/方程；
- 如何被数据、题面或文献支持；
- 若不成立，结论会怎样变化。

关键变量必须在以下位置口径一致：

```text
符号表
↔ 数学公式
↔ 程序输入输出
↔ 验证
↔ 表图
↔ 论文结论
```

公式只保留决定模型含义的目标、状态关系、关键约束、指标和重要变换。标准算法步骤不需要堆成公式数量。

## 6. Baseline 与模型选择质量

### 6.1 Baseline 的职责

Baseline 必须与主模型输出可比较，并承担至少一个作用：

- 证明任务本身是否困难；
- 量化复杂模型的增益；
- 暴露简单模型失败点；
- 为论文结果提供统一参照。

### 6.2 Model Ladder

默认模型梯子：

```text
简单规则/经典 baseline
→ 结构匹配的经典主模型
→ 针对已观察失败点的升级
→ 轻量 challenger
→ 保留或回退
```

每个新增复杂模型都必须说明：

1. baseline/main 在哪里失败；
2. 新结构具体修复什么；
3. 用什么实验能证伪该改进；
4. 如果收益不稳定，回退到什么。

不能只凭“文献常用”“算法先进”“模型精度可能更高”升级。

## 7. 各类任务的核心证据

### 7.1 预测/回归

优先证据：

- naive/seasonal/simple regression baseline；
- 时间外、滚动或结构匹配的样本外验证；
- 主指标与区间；
- 分组/高代价区域误差；
- residual/bias/calibration（按模型需要）；
- 预测窗口变化后的稳定性。

训练内拟合不能写成预测能力。

### 7.2 分类

优先证据：

- prevalence/simple-rule baseline；
- 与误判代价匹配的 Precision/Recall/F1/PR-AUC；
- confusion matrix；
- threshold sensitivity；
- 若概率用于决策，检查 calibration；
- subgroup error。

Accuracy 不能单独支撑不平衡分类结论。

### 7.3 评价/排序

优先证据：

- equal-weight/simple rule baseline；
- 指标方向与标准化；
- 权重来源；
- 权重扰动；
- 删指标稳定性；
- top-k / 排名稳定性。

综合得分是构造量，不自动具有绝对物理意义。

### 7.4 优化/调度

优先证据：

- 可行性和硬约束；
- rule/greedy/simple LP baseline；
- 小规模精确解、LP relaxation、bound 或 solver gap（能获得时）；
- 资源/调度方案本身；
- 压力场景与敏感性；
- 随机算法多种子。

收敛曲线只证明搜索行为，不能单独证明方案优越或全局最优。

### 7.5 多目标

固定一个权重只得到给定偏好下的单方案。只有实际探索多个权重、epsilon 或非支配解时，才能讨论 Pareto 权衡范围。

推荐点必须解释：

- 权衡依据；
- knee/偏好来源；
- 关键目标牺牲与收益；
- 对权重或场景的稳定性。

### 7.6 机理/仿真

优先检查：

- 量纲；
- 初值/边界；
- 守恒/非负/容量不变量；
- 极限情形；
- 参数来源与可辨识性；
- 数值步长/离散敏感性；
- 观测校准与外推边界。

拟合好不自动等于机制正确。

### 7.7 统计推断

报告优先级：

```text
效应方向和大小
→ 不确定性区间
→ 稳健替代
→ p 值
```

不得用 p<0.05 代替实际意义；多重检验必须考虑选择偏差；相关不写成因果。

### 7.8 聚类/网络

聚类重点是结构稳定性和现实可解释性，而非单一 silhouette；网络重点是节点、边、方向、容量和单位映射正确，并通过小实例/守恒/容量检查验证。

## 8. 实验设计：信息增益优先

实验不是数量竞赛。默认每问优先获得：

```text
baseline comparison
+ 1 个题型专项验证
+ 1 个 robustness/sensitivity
+ 1 个 failure-case / stress test
```

只有结果可能改变以下判断时才追加实验：

- 是否保留主模型；
- 是否增加复杂度；
- claim 能否扩大；
- 哪个参数/场景最关键；
- 哪个图表值得进入论文。

### 8.1 消融

只有模型真实存在多个模块并声称模块有贡献时才做。没有模块化结构时不要为了“论文形式”制造消融。

### 8.2 超参数

顺序为：默认/合理参数跑通 → 粗粒度搜索 → 只对敏感参数细调。若复杂模型只带来微小、波动性增益，应优先把时间投入验证与论文。

## 9. 证据与 Claim 梯子

正式表述按以下层级递进：

```text
Observation
→ Quantitative result
→ Comparison
→ Interpretation
→ Decision implication
→ Boundary
```

禁止跳级，例如：

- 看到相关 → 直接写因果；
- 一次启发式最优 → 写全局最优；
- 一个场景稳定 → 写普遍鲁棒；
- 训练精度高 → 写泛化能力强；
- 固定权重方案 → 写完整 Pareto 前沿。

## 10. 可视化与表格学术质量

每个图表先有 reader question。

选择原则：

- 精确数字比较 → table；
- 趋势、分布、关系、空间、权衡、失败模式 → figure；
- 1–3 个关键数字 → text；
- 无新增信息 → none。

论文图优先承担一种职责：

- **Result Figure**：得到什么；
- **Validation Figure**：为什么可信；
- **Mechanism Figure**：为什么产生结果。

主模型应视觉突出，baseline 中性化；颜色不能作为唯一编码。禁止 3D 装饰、彩虹色谱、重复表图和只为“好看”存在的图。

图注至少说明比较对象、主要编码、必要的不确定性/场景和读者应关注的结论，但不替代正文解释。

## 11. 论文的学术叙事

优秀论文常见稳定结构不是固定标题，而是稳定论证关系：

```text
题面交付
→ 问题分析
→ 假设与变量
→ 模型选择理由
→ 数学模型
→ 求解/算法
→ 结果
→ 验证
→ 实际解释
→ 边界
```

### 11.1 摘要

摘要不是模型目录。每问优先包含：对象/目标、关键方法、1–2 个主结果、baseline/参考比较、验证和边界。评委不看正文也应知道每问做了什么、得到了什么。

### 11.2 问题分析

重点解释“为什么这样建模”，不要提前堆算法名字。

### 11.3 模型建立

核心公式后立即解释变量、单位、现实意义和假设依据。

### 11.4 结果

主要段落采用：

```text
结果
→ 比较
→ 原因/机制
→ 实际意义
→ 边界
```

### 11.5 每问结尾

直接写最终答案/方案、优势、可信依据、适用条件和交给下一问的输出。

### 11.6 模型评价

优点和局限必须针对本文具体模型和证据，不写模板化“准确性高、鲁棒性强、推广性好”。

## 12. 文献使用质量

文献不是为了增加参考文献数量，而应回答：

- 这个模型在哪些条件下成立；
- 关键参数/阈值有什么依据；
- 哪种验证是该类方法常规或必要的；
- 题目背景中的实际机制是什么；
- 当前方案相对已有方法有什么结构性差异。

优先原始论文、权威教材、标准和高质量综述。引用必须与紧邻陈述存在真实支持关系；不得用一篇引用支撑整段无关结论。

## 13. 自我反驳：每个候选必须经历一次

在模型晋升前，至少回答：

1. **最强替代解释是什么？**
2. **哪个假设一旦失效最可能改变结论？**
3. **哪个数据切分/场景最容易让当前结果失败？**
4. **简单 baseline 是否已经足够？**
5. **主模型的改善是否大到值得复杂度？**
6. **有没有把相关、局部、样本内或固定偏好结果写得过强？**

如果这些问题暴露实质问题，优先修模型/验证，不要用文字掩盖。

## 14. 停止规则

满足以下条件后优先停止扩模型：

- 题面主输出完整；
- baseline 可比；
- 主模型解决了明确难点；
- challenger 没有形成稳定优势，或主模型优势已足够；
- 最重要失败风险已被验证；
- 主结论在合理扰动/场景下稳定；
- 新增复杂度的预期收益低于完善证据、图表和论文的收益。

停止探索不是“做少了”，而是把比赛资源转向最能提高最终论文质量的部分。

## 15. 禁止的低质量模式

- Model zoo：罗列很多模型但没有选型逻辑；
- 指标挑选：只报告对主模型有利指标；
- p-value worship：把显著性当效果大小；
- leaderboard thinking：只因分数最高选模型；
- silent fallback：算法失败后静默换成另一方法仍用原算法名；
- synthetic evidence：示例/随机数据进入正式结论；
- chart decoration：图没有明确 reader question；
- causal overclaim：相关/Granger/feature importance 写成因果；
- global overclaim：局部/采样/启发式结果写成全局；
- formula inflation：为显得复杂堆公式；
- checklist theater：机械完成固定“误差+灵敏度+稳健性”而不对应真实风险；
- adjective substitution：用“先进、准确、鲁棒、创新”替代定量证据。

## 16. 最终评委视角七问

假设评委只读摘要、问题分析、每问主图/主表和结论，他应能回答：

1. 每一问到底解决了什么；
2. 为什么这个模型适合；
3. 最重要的定量结果是什么；
4. 相比简单方案好在哪里；
5. 为什么结果可信；
6. 对实际问题有什么决策/解释价值；
7. 在哪里可能失效。

七问中任意一项回答不出来，优先补相应内容，而不是继续扩展算法数量。
