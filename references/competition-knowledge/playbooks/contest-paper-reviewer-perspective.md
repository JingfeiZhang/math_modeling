# 国赛评阅者视角：模型—证据—论文一致性

> 定位：P1–P5 的非正式质量手册。用于帮助 Solver、Paper、Reviewer 从“评阅者会因什么降分”反推建模与论文决策。
>
> 来源基础：仓库外部培训资料《数学建模竞赛赛题选讲》《数学建模竞赛注意事项与经验分享》的评阅要点与案例讲解，经本项目学术质量标准筛选后提炼。原资料不是当届官方评分细则，具体历史题结论、软件偏好和经验性“加分项”不作为规则。

## 1. 评阅顺序：先审问题是否建对，再看算法是否漂亮

高质量答卷首先通过以下五问：

1. **目标定义是否真的对应题面交付？**
2. **关键约束是否完整，变量域是否正确？**
3. **模型、程序、结果三者是否一致？**
4. **方案是否先可行，再比较目标值或性能？**
5. **结论是否只覆盖实际验证过的数据、场景和搜索范围？**

推荐审查顺序：

```text
题意与目标
→ 变量/参数角色
→ 约束完整性
→ baseline / known-answer
→ 代码实现一致性
→ 可行性/样本外有效性
→ 比较与不确定性
→ 结论和边界
→ 表达与版面
```

不要把“算法复杂”“图很多”“公式多”放在前面。

## 2. Objective correctness：目标函数错，后面越精确越危险

优化、评价和多目标问题最常见的根本错误之一是目标定义与题面真实需求不一致。

每个目标必须回答：

- 题面原句要求优化/评价的是什么？
- 目标变量或指标的单位是什么？
- 最大化/最小化方向是否正确？
- 是否遗漏题面中的次级目标、服务水平或风险要求？
- 若使用代理指标，为什么它能代表原目标？
- 多目标合成时，权重代表什么偏好？

### Reviewer checkpoint

若把目标从原始题意换成代理量，必须至少提供一条：

- 数学等价关系；
- 业务解释；
- 文献/题面依据；
- 对最终决策不敏感的验证。

否则只能写“在该代理目标下的最优/较优方案”。

## 3. Constraint completeness：约束不是附属品，是模型本体

对优化/调度/资源配置题，先做 Constraint Inventory，再写 solver。

至少分类：

| 类别 | 典型内容 | 审查问题 |
|---|---|---|
| 容量 | 面积、库存、预算、资源上限 | 单位和时间尺度一致吗？ |
| 兼容性 | 地块—作物、任务—机器、人员—技能 | 是否遗漏禁止组合？ |
| 时间 | 季次、工期、先后关系、轮作 | 跨期耦合是否真实建模？ |
| 逻辑 | 若…则…、互斥、至少/至多 | 0-1 变量和 Big-M 是否合理？ |
| 服务 | 覆盖率、满足率、最低需求 | 是硬约束还是软目标？ |
| 风险 | 最坏场景、概率约束、波动 | 不确定性是否进入模型？ |
| 变量域 | 连续、整数、0-1、非负 | 求解器变量域与论文一致吗？ |

一个高目标值但违反一条关键约束的方案不能参与“优劣比较”。

## 4. General model before instance result

历史赛题评阅经验反复体现一个原则：

> 先给能描述一般情形的模型/算法，再把具体附件数据代入；不要只针对一个实例手工拼结果。

论文至少应让评阅者知道：

- 决策变量/状态变量的一般定义；
- 输入数据如何进入模型；
- 约束如何随规模扩展；
- 输出如何从一般模型生成；
- 哪些地方是本题特例。

这并不要求为了“普适”把模型写得抽象难懂；目标是证明结果来自模型，而不是人工调出来。

## 5. Model ↔ Code ↔ Result parity

正式结果进入 claims 前，逐项核对：

```text
论文中的变量与公式
↔ runner 中的变量、约束、目标
↔ 实际输入数据
↔ 结果表/图
↔ 最终结论
```

典型失败：

- 论文写 MILP，代码实际是启发式近似；
- 论文写“满足全部约束”，代码没有实现某条逻辑约束；
- 论文写某指标，程序输出的是另一种分母/窗口；
- 图中数字来自旧 run，而正文来自新 run；
- 论文写多目标 Pareto，实际上只跑了单一固定权重。

Formal promotion 必须优先阻断这些 parity 问题。

## 6. Feasibility first, objective second

优化结果比较统一遵循：

```text
solver status
→ feasibility audit
→ integrality / invariant audit
→ objective / utility comparison
→ optimality evidence
```

不允许：

```text
目标值更大
→ 直接宣布方案更优
```

如果不同算法得到的方案可行率不同，应先报告可行率/违反量，再在同一可行集合或同等约束条件下比较目标。

## 7. Heuristic / metaheuristic 的额外证据责任

启发式和元启发式不能因为“收敛曲线好看”就承担最优性 claim。

至少按可获得条件提供：

- 小规模精确解或枚举；
- LP relaxation / lower bound / upper bound；
- 多随机种子；
- 多实例或多场景；
- 可行率；
- 与简单规则/经典算法 baseline 比较；
- 计算预算或停止条件。

措辞：

- 有 exact/gap 证据时：按证据写最优性范围；
- 无 exact 证据时：写“当前搜索预算下最优可行候选”或“近似 Pareto 解集”，不要写“全局最优”。

## 8. 信息边界：离线、在线、随机问题不能混写

先判断决策时点能看到什么信息：

### 确定性离线

决策前已知完整实例信息，可讨论 exact / gap / instance optimum。

### 在线 / 部分信息未知

策略必须是：

```text
当前可观察状态
→ 决策规则
→ 下一状态
```

不能使用未来天气、未来需求、未来价格等信息。

### 随机 / 不确定

必须定义评价标准，例如：

- 期望收益；
- 分位数/尾部风险；
- 最坏场景；
- 服务水平；
- regret。

再比较策略，而不是只给一个确定性最优方案。

## 9. Reviewer 的对抗性问题

每一问至少主动提出一个可能推翻当前结论的问题：

- 如果删掉一个关键指标，排名会变吗？
- 如果需求提高/下降，方案仍可行吗？
- 如果时间切分后，预测优势还在吗？
- 如果换一个随机种子，启发式结论还在吗？
- 如果代理目标换成原始业务指标，模型还占优吗？
- 如果一条边界假设不成立，结论应降级到什么程度？

能被这些问题推翻的 claim，必须先缩小边界或补实验。

## 10. 论文层的高信息密度审查

评阅者快速阅读时，应能从以下位置恢复整篇论文主线：

- 摘要；
- 问题分析；
- 每问主模型定义；
- 核心表/图标题和 caption；
- 每问结尾；
- 模型评价。

每问建议保持：

```text
直接回答
→ 为什么这样建模
→ 关键定量结果
→ baseline/参考比较
→ 可信证据
→ 实际意义
→ 适用边界
```

## 11. 明确不吸收的历史经验

以下只属于原培训资料的年代/个人经验，不进入当前硬规则：

- 特定软件（MATLAB/LINGO/Word/MathType）优先级；
- “多用算法就加分”；
- “固定 ±5%、±10% 灵敏度”；
- 某历史实例中某聚类/启发式“效果最好”向其他题泛化；
- 以模型数量、公式数量或装饰性图表衡量质量。

## 12. 触发条件

优先在以下场景读取本手册：

- P1：目标/约束复杂或多问耦合；
- P3：需要比较 exact / heuristic / challenger；
- P4：准备 Formal promotion / claims freeze；
- P5：Reviewer 审论文是否过度主张。

本手册只改变“审什么”，不新增 Gate。
