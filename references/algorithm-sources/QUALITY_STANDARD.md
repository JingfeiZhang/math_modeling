# 算法参考与模板质量标准

本文件规定 `references/algorithm-sources/`、`代码库/` 及其算法卡/模板在 P1–P3 的使用方式。目标是让参考代码成为**建模决策辅助**，而不是“换数据即用”的套模工具。

它不改变 `study_only` 边界：参考实现、示例数据、示例图和示例数值不能直接成为 Formal Evidence；正式代码必须在当前项目内按题面重新实现并验证。

## 1. 一张高质量算法卡必须回答什么

每种候选方法至少回答以下问题：

1. **Method identity**：它实际是什么算法/求解器，不能用营销名称代替；
2. **Trigger**：什么数据结构/数学结构出现时值得考虑；
3. **Non-trigger**：什么情况下不应使用；
4. **Assumptions**：成立所需的统计、数学或机理条件；
5. **Input contract**：输入形状、单位、时序/分组边界、缺失与尺度要求；
6. **Output contract**：输出是什么，是否与题面主指标可比较；
7. **Baseline**：至少一个同输出简单参照；
8. **Validation**：哪类证据能证明其正确性/泛化/可行性；
9. **Known failure modes**：最常见错误和误用；
10. **Upgrade condition**：什么证据出现后才值得从简单模型升级；
11. **Fallback**：复杂模型不稳定时退到什么；
12. **Paper evidence**：最终论文应报告什么，而不是介绍多少算法原理；
13. **Claim boundary**：哪些结论不能由该方法单独推出；
14. **Reimplementation requirements**：进入当前项目时必须重写/核对什么。

算法卡如果只回答“怎么调用”，质量不合格。

## 2. 参考代码的定位

参考代码可用于：

- 理解公式与 API；
- 快速构造 known-answer 小例子；
- 发现 baseline 候选；
- 设计失败探针；
- 比较实现复杂度；
- 验证环境依赖。

参考代码不可直接用于：

- Formal 数字；
- claims；
- 论文图表；
- submission/release；
- 未经重写的数据处理；
- 未经核验的默认参数；
- 示例中的经验阈值和结论。

## 3. 正式采用一个算法前的最小决策记录

进入 Candidate 前，至少能回答：

```text
题面难点是什么？
→ baseline 哪里失败？
→ 该算法增加了什么结构？
→ 这项结构为什么与失败点匹配？
→ 哪个实验能证伪它？
→ 如果失败回退到什么？
```

如果只能回答“这个算法常用/精度高/比较高级”，则不应升级。

## 4. 代码模板的接口质量

模板核心函数优先返回结构化结果，而不是只 `print()`：

```python
{
    "method": "...",
    "status": "...",
    "prediction_or_solution": ...,
    "primary_metric": ...,
    "diagnostics": {...},
    "seed": ...,
    "warnings": [...],
}
```

具体字段可因方法变化，但至少应区分：

- 求解/拟合是否成功；
- 主结果；
- 诊断信息；
- 失败/警告；
- 随机性来源。

示例脚本可打印结果用于学习，但正式 runner 应消费结构化输出。

## 5. 禁止 silent fallback

如果模板原方法不可用，不能悄悄换成另一个算法还使用原方法名称。

错误示例：

```text
TensorFlow 不存在
→ 自动改用 MLP
→ 仍显示 LSTM prediction
```

正确处理：

- 明确失败并提示依赖缺失；或
- 显式返回 `fallback_method=MLP`；
- 把 fallback 作为另一个候选模型独立评价。

算法身份变化必须进入实验回执和论文边界。

## 6. 数据处理不能隐藏在模板里改变研究设计

模板可以演示 scaler、imputer、编码器和特征构造，但必须清楚区分：

```text
fit on train
transform validation/test
```

禁止在完整数据上先拟合预处理器再做验证。时间、空间、主体分组数据必须保留相应边界。

## 7. 随机算法的可复现性

涉及随机初始化、抽样、启发式或随机训练时：

- seed 必须显式可传；
- 不只保存最好一次；
- 比较算法时使用公平预算；
- 报告多个种子的中心与离散程度；
- 随机数生成器尽量局部化，不污染全局状态。

## 8. 各领域参考标准

### 8.1 预测/回归

候选优先级：naive/simple baseline → classical structured model → nonlinear model → deep model（有数据与证据时）。

必须防：

- 时间随机切分；
- 全序列选阶；
- 用 validation/test 调参数；
- 只报告训练拟合；
- MAPE 零值问题；
- 多步递归误差被隐藏。

论文优先报告样本外主指标、baseline、预测窗口、区间/分组误差和失败时段。

### 8.2 分类

必须先定义类别基率、误判代价和阈值。严重不平衡时不能只用 Accuracy。概率进入决策时应检查校准。

### 8.3 聚类

聚类模板必须明确距离/尺度假设、k/密度参数来源、初始化稳定性和现实解释。t-SNE/UMAP 仅用于辅助展示，不能作为聚类正确性的主要证据。

### 8.4 评价/排序

必须记录指标方向、尺度、权重来源和 equal-weight/simple baseline。结果应做权重/删项稳定性；综合得分不能写成天然客观真值。

### 8.5 精确优化

LP/MILP/QP/网络流等模板必须返回 solver status、可行性和关键约束检查。若能获得 gap/bound，优先记录。整数问题禁止“连续解四舍五入后当最优解”。

### 8.6 非线性优化

必须说明凸性/局部性风险；多初值只能降低局部解风险，不能自动证明全局最优。若有可用 lower bound、小规模精确参考或已知解，应优先比较。

### 8.7 元启发式

GA/PSO/SA/DE/ACO/NSGA-II 等只在精确/简单路线不适用或预算受限时使用。必须多种子、公平函数评估预算、可行性回查，并明确“近似/有限预算”措辞。

### 8.8 多目标

固定一个权重解不能称为完整 Pareto 前沿。必须记录实际扫描范围、非支配解数量、推荐点规则和稳定性。

### 8.9 统计推断

模板必须区分估计、检验、预测和因果问题。优先 effect size + interval；p 值不等于实际意义。重复检验要考虑多重比较。

### 8.10 网络

模板必须明确节点、边、方向、权重、容量和单位。Dijkstra/MST/max-flow 等算法只能用于满足相应结构的网络。

### 8.11 机理模型

核心不是 `solve_ivp` 调用，而是状态变量、量纲、守恒、边界、参数来源和可辨识性。数值求解成功不能代替机制验证。

### 8.12 组合模型

只有组件承担互补职责且单模型存在已验证缺口时才组合。必须做公平组件 baseline/消融；复杂名称不是创新证据。

## 9. 验证模板必须“按风险选”，不能固定三件套

不存在所有模型都必须完成同一组“误差分析 + 灵敏度分析 + 稳健性分析”的学术硬规则。

应按任务风险选择：

- 预测：时间外/滚动、残差、区间、分组误差；
- 分类：混淆矩阵、PR、阈值、校准；
- 优化：可行性、bound/gap、小实例、压力场景；
- 评价：权重和排名稳定性；
- 机理：量纲、守恒、边界、极限、敏感性；
- 统计：效应量、区间、假设/稳健替代；
- 随机算法：多种子与预算公平性。

“验证”是针对最可能失败的地方，不是完成固定 checklist。

## 10. 示例数据与 known-answer

示例数据只用于演示接口。更高价值的是小型 known-answer fixture：

- 可人工计算；
- 可穷举；
- 有解析解；
- 可由精确 solver 验证。

模板如果适合，应附一个小例子验证约束、方向或指标公式，而不是只展示一张漂亮图。

## 11. 论文中如何使用算法参考

正式论文不需要写“代码库提供了某算法”。论文只描述当前项目实际采用的方法和证据。

算法介绍压缩到足够理解本文模型的程度，优先写：

```text
为什么选
→ 本文如何适配
→ 关键公式/约束
→ 如何验证
→ 得到了什么
```

而不是复制教材式算法步骤。

## 12. 模板质量回退规则

遇到以下情况，优先回退简单模型或停止使用模板：

- 输入结构与题面不一致；
- 模板隐含假设无法成立；
- baseline 已经同等好；
- 复杂模型增益不稳定；
- 模板存在信息泄漏；
- 依赖不可用且需要换算法身份；
- 无法形成与题面主指标对应的输出；
- 无法完成与任务匹配的验证。

参考代码的价值是缩短“理解—重写—验证”的时间，而不是缩短到“复制—改参数—交论文”。
